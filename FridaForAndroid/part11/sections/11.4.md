# 11.4 Cocos2d-js 游戏 XXTEA 密钥提取

> 核心要点：Cocos2d-js 引擎使用 XXTEA 算法对游戏脚本和资源进行加密。通过 Frida Hook 动态库中的 `dlopen` 和 `xxtea_decrypt` 函数，可以在游戏运行时的第一时间捕获解密密钥。

## 1. Cocos2d-js 加密机制

Cocos2d-js 是 Cocos2d-x 引擎的 JavaScript 绑定版本。为了保护游戏脚本和资源文件，Cocos2d-js 使用 XXTEA（Corrected Block TEA）加密算法对 `.js` 和资源文件进行加密。

**XXTEA 加密流程：**

```
游戏打包时：
    源文件（.js / .png / .plist）
        ↓
    XXTEA 加密（使用密钥 key）
        ↓
    加密后的文件打包到 APK 的 assets/ 目录
        ↓
游戏运行时：
    libcocos2djs.so 加载
        ↓
    xxtea_decrypt(key, data, len) 被调用
        ↓
    ❗ Hook xxtea_decrypt 的第三个参数即可捕获密钥
```

## 2. cocos2djs-xxtea-key.js 完整分析

> **引用源文件**：`awesomeFrida/cocos2djs-xxtea-key.js`（完整75行代码）

### 2.1 脚本结构与参数（第26-29行）

```javascript
// 引用：awesomeFrida/cocos2djs-xxtea-key.js 第26-29行
// 目标动态库名称
var TARGET_LIB_NAME = "libcocos2djs.so";

// 目标函数名称
var TargetFuncName = "xxtea_decrypt";
```

两个关键配置参数：
- `TARGET_LIB_NAME`：目标 SO 文件名。Cocos2d-js 游戏的核心动态库，不同游戏版本可能命名不同（如 `libcocos2djs.so`、`libcocos2djs-cpp.so`）
- `TargetFuncName`：XXTEA 解密函数名，标准实现为 `xxtea_decrypt`

### 2.2 Hook 目标函数（第34-50行）

```javascript
// 引用：awesomeFrida/cocos2djs-xxtea-key.js 第34-50行
function do_hook() {
    // 查找目标函数的地址
    var addr = Module.findExportByName(TARGET_LIB_NAME, TargetFuncName);
    console.log("找到目标函数地址:", addr);

    // 挂载目标函数
    Interceptor.attach(addr, {
        onEnter: function (args) {
            // args[2] 是目标函数的第三个参数（假设是密钥）
            // 读取并打印密钥
            console.log("捕获到的密钥: " + Memory.readCString(args[2]));
        },
        onLeave: function (retval) {
            // 函数返回时的操作（此处无操作）
        }
    });
}
```

**关键点说明：**

| 参数 | 含义 |
|:---:|:---|
| `args[0]` | 第一个参数 — 待解密的数据指针 |
| `args[1]` | 第二个参数 — 数据长度 |
| `args[2]` | 第三个参数 — **XXTEA 密钥字符串指针** |
| `args[3]` | 第四个参数 — 解密后的数据长度指针（输出） |

`Memory.readCString(args[2])` 从 Native 层读取 C 风格字符串，获取 XXTEA 密钥。

> **注意**：在某些自定义实现的 Cocos2d-js 引擎中，参数顺序可能被修改。如果捕获到的密钥内容异常，需要通过逆向分析确认实际的参数顺序。

### 2.3 dlopen 延迟 Hook（第53-74行）

```javascript
// 引用：awesomeFrida/cocos2djs-xxtea-key.js 第53-74行
function hook_dlopen() {
    ["android_dlopen_ext", "dlopen"].forEach(funcName => {
        let addr = Module.findExportByName(null, funcName);
        if (addr) {
            Interceptor.attach(addr, {
                onEnter(args) {
                    let libName = ptr(args[0]).readCString();
                    if (libName && libName.indexOf(TARGET_LIB_NAME) >= 0) {
                        this.is_can_hook = true;
                        console.log(`[+] ${funcName} onEnter: ${libName}`);
                    }
                },
                onLeave: function (retval) {
                    if (this.is_can_hook) {
                        console.log(`[+] ${funcName} onLeave, start hook ${TargetFuncName}`);
                        do_hook();
                    }
                }
            });
        }
    });
}

hook_dlopen();
```

**延迟 Hook 的必要性：**

```
时间轴：
Frida 注入 → App 启动 → libcocos2djs.so 尚未加载
                                        ↓
                           dlopen("libcocos2djs.so") 被调用
                                        ↓
                           onEnter: 检测到目标 SO 加载，标记 is_can_hook
                                        ↓
                           onLeave: SO 加载完成，执行 do_hook()
                                        ↓
                           xxtea_decrypt 被游戏调用 → 捕获密钥！
```

如果不使用延迟 Hook，当 Frida 注入时 `libcocos2djs.so` 可能尚未加载，`Module.findExportByName` 会找不到目标函数。

`hook_dlopen()` 同时 Hook `dlopen` 和 `android_dlopen_ext`（Android 5.0+ 使用的扩展版本），确保兼容不同 Android 版本。

## 3. 完整使用流程

### 3.1 确定目标库名称

```bash
# 方法一：从 APK 中查找
unzip -l game.apk | grep libcocos2d

# 方法二：启动游戏后用 Frida 枚举模块
frida -U com.example.game -l enum-modules.js
```

`enum-modules.js`:

```javascript
// 枚举所有已加载模块
Process.enumerateModules({
    onMatch: function(module) {
        if (module.name.indexOf("cocos") >= 0 ||
            module.name.indexOf("libcocos") >= 0) {
            console.log(module.name);
        }
    },
    onComplete: function() {
        console.log("Done");
    }
});
```

### 3.2 确认 xxtea_decrypt 函数名

如果标准名称 `xxtea_decrypt` 找不到，可以尝试其他常见名称：

```javascript
var candidates = [
    "xxtea_decrypt",
    "XXTEA_decrypt",
    "xxteaDecrypt",
    "cc_xxtea_decrypt",
    "xxtea_decrypt_"
];
```

或者直接枚举导出符号：

```javascript
var module = Process.getModuleByName("libcocos2djs.so");
module.enumerateExports().forEach(function(exp) {
    if (exp.name.toLowerCase().indexOf("xxtea") >= 0) {
        console.log(exp.name + " @ " + exp.address);
    }
});
```

### 3.3 运行脚本

```bash
# Spawn 模式（推荐，可捕获 dlopen 全过程）
frida -U -l cocos2djs-xxtea-key.js -f com.example.game --no-pause

# 或者 Attach 到运行中的进程
frida -U -l cocos2djs-xxtea-key.js com.example.game
```

## 4. 常见问题与排查

| 问题 | 可能原因 | 解决方案 |
|:---|:---|:---|
| **找不到 dlopen 地址** | Frida 版本过低或 SELinux 限制 | 升级 Frida，检查 SELinux 状态 |
| **捕获不到 xxtea_decrypt** | 函数名不匹配 | 枚举导出符号确认函数名 |
| **捕获到的密钥内容异常** | 参数位置不正确 | 逆向 xxtea_decrypt 确认参数顺序 |
| **脚本未触发** | SO 加载时间早于注入 | 使用 spawn 模式启动 |
| **多个密钥** | 不同资源使用不同的密钥 | 收集所有密钥逐一尝试 |

## 5. 进阶：自定义 XXTEA 实现追踪

如果游戏修改了 XXTEA 源码（重命名函数或改变参数顺序），需要逆向分析：

```javascript
// 通用方案：在 SO 加载后，搜索特征字节定位 xxtea 函数
function locate_xxtea() {
    var module = Process.getModuleByName(TARGET_LIB_NAME);
    // XXTEA 的 DELTA 常量 0x9E3779B9
    var pattern = "B9 79 37 9E"; // little-endian
    
    var matches = Memory.scanSync(module.base, module.size, pattern);
    matches.forEach(function(match) {
        console.log("Found XXTEA delta at: " + match.address);
    });
}
```

## 小结

- **Cocos2d-js 游戏**使用 XXTEA 加密脚本和资源，密钥在运行时通过 `xxtea_decrypt` 参数传递
- **延迟 Hook 技术**是此方案的核心：先 Hook `dlopen` 等待 SO 加载，再 Hook 目标函数
- **`Memory.readCString()`** 用于从 Native 层读取 C 风格的密钥字符串
- 此思路可推广到其他使用 XXTEA/LZ4/自定义加密的游戏引擎逆向

> **参考源文件**：`awesomeFrida/cocos2djs-xxtea-key.js`（完整75行代码）实现了完整的 dlopen 拦截 + xxtea_decrypt Hook 的密钥提取方案。
