# 11.7 Frida Gadget 集成与免 root 注入

> 核心要点：Frida Gadget 是 Frida 的动态链接库形式，可以直接嵌入到 APK 中，实现无需 root 权限的 Frida 注入。这在 root 受限的设备、生产环境 App 分析、以及企业安全测试等场景下至关重要。

## 1. 什么是 Frida Gadget

### 1.1 基本概念

Frida Gadget 是 Frida 的 SO 库形态。它将 Frida 的 Agent 运行时编译为动态链接库（.so），可以被嵌入到目标 App 的 APK 中，随 App 启动时自动加载。

**与传统 Frida 注入对比：**

| 特性 | 传统 Frida（frida-server） | Frida Gadget |
|:---:|:------------------------:|:------------:|
| **root 权限** | 需要 | 不需要 |
| **注入方式** | frida-server 远程注入 | 内嵌入 APK |
| **适用场景** | 已 root 设备 | 任何设备 |
| **检测难度** | 易被检测 | 可伪装隐藏 |
| **配置灵活性** | 运行时动态 | 编译期配置 |
| **重打包** | 不需要 | 需要 |

### 1.2 Frida Gadget 的两种模式

| 模式 | 说明 | 适用场景 |
|:---:|:---|:---|
| **listen** | Gadget 在 App 中启动 TCP 监听，等待 Frida 工具连接 | 调试阶段，交互式分析 |
| **script** | Gadget 自动加载指定的 JS 脚本 | 生产环境，自动化分析 |

## 2. 下载与编译 Frida Gadget

### 2.1 预编译版本下载

```bash
# 从 GitHub Releases 下载
# https://github.com/frida/frida/releases

# 下载对应架构的 Gadget
# ARM64（主流）
wget https://github.com/frida/frida/releases/download/{version}/frida-gadget-{version}-android-arm64.so.xz

# ARM32（兼容旧设备）
wget https://github.com/frida/frida/releases/download/{version}/frida-gadget-{version}-android-arm.so.xz

# x86（模拟器）
wget https://github.com/frida/frida/releases/download/{version}/frida-gadget-{version}-android-x86.so.xz

# 解压
xz -d frida-gadget-*-android-arm64.so.xz
```

### 2.2 自定义编译

```bash
# 使用 frida-tools 中的工具编译
# 从源码构建
git clone https://github.com/frida/frida.git
cd frida
make core-android-arm64
```

## 3. 将 Gadget 嵌入 APK

### 3.1 手动重打包（最常用）

```bash
# 1. 解压 APK
apktool d target.apk -o target_dir

# 2. 复制 Gadget 到 lib 目录
# 确定目标架构（通常 lib/arm64-v8a/ 或 lib/armeabi-v7a/）
cp frida-gadget-android-arm64.so target_dir/lib/arm64-v8a/libfrida-gadget.so

# 3. 创建 Gadget 配置文件（可选）
# 在 target_dir/assets/ 下创建 frida-gadget.config.json

# 4. 修改 AndroidManifest.xml 确保 lib 被加载
# 如果需要，添加 android:extractNativeLibs="true"

# 5. 重新打包并签名
apktool b target_dir -o target_patched.apk
jarsigner -keystore my.keystore -storepass password \
    -sigalg SHA1withRSA -digestalg SHA1 \
    target_patched.apk alias_name

# 6. 安装重打包的 APK
adb install target_patched.apk
```

### 3.2 使用 objection 自动集成

```bash
# objection 提供了 patchapk 命令自动完成重打包
# 下载对应架构的 frida-gadget.so 后：

objection patchapk -s target.apk \
    -g /path/to/frida-gadget-android-arm64.so

# 或者让 objection 自动下载 Gadget
objection patchapk -s target.apk

# 安装修补后的 APK
adb install target.objection.apk
```

## 4. Gadget 配置文件

> 配置文件放在 APK 的 `assets/frida-gadget.config.json`

### 4.1 listen 模式配置

```json
{
    "interaction": {
        "type": "listen",
        "address": "127.0.0.1",
        "port": 27042,
        "on_port_conflict": "pick-next",
        "on_load": "wait"
    }
}
```

**连接方式：**

```bash
# Gadget 启动后会自动监听 127.0.0.1:27042
# 使用 Frida 连接（需要 adb forward）
adb forward tcp:27042 tcp:27042

# 通过 USB 连接
frida -H 127.0.0.1:27042

# 或直接在手机上通过本地端口连接
frida-ps -H 127.0.0.1:27042
```

### 4.2 script 模式配置

```json
{
    "interaction": {
        "type": "script",
        "on_change": "reload",
        "directory": "/data/local/tmp/frida-scripts"
    }
}
```

**工作原理：**

```
App 启动
    ↓
Gadget 加载
    ↓
读取配置文件
    ↓
script 模式 → 监控 /data/local/tmp/frida-scripts/ 目录
    ↓
自动加载该目录下的所有 .js 文件
    ↓
当 .js 文件发生变化时自动重新加载（热更新）
```

### 4.3 配置文件参数详解

| 参数 | 可选值 | 说明 |
|:---:|:------|:----|
| `type` | `listen` / `script` | 运行模式 |
| `address` | IP 地址 | listen 模式的监听地址 |
| `port` | 端口号 | listen 模式的监听端口 |
| `on_port_conflict` | `fail` / `pick-next` | 端口冲突处理方式 |
| `on_load` | `wait` / `resume` | 加载后是否等待连接 |
| `on_change` | `reload` / `ignore` | 脚本文件变化时的行为 |
| `directory` | 路径 | script 模式监控的目录 |

## 5. 免 root 场景的变通方案

### 5.1 修改类加载器加载 Gadget

如果 App 在 Java 代码中有加载 SO 的逻辑，可以通过插入 `System.loadLibrary` 调用：

```bash
# 方案：在 smali 代码中插入 System.loadLibrary 调用
# 找到应用入口 Activity 或 Application 的 smali 代码

# 在 onCreate 方法中插入
invoke-static {v0}, Ljava/lang/System;->loadLibrary(Ljava/lang/String;)V
# 其中 v0 = "frida-gadget"
```

### 5.2 使用 frida-inject

`frida-inject` 是另一种免 root 方案，适用于已 root 但不想安装 frida-server 的场景：

```bash
# 将 frida-inject 推送到设备
adb push frida-inject /data/local/tmp/
adb shell chmod 755 /data/local/tmp/frida-inject

# 注入目标进程
adb shell "/data/local/tmp/frida-inject \
    -n com.example.app \
    -s /data/local/tmp/script.js"
```

### 5.3 使用 Frida-Gadget 隐藏技巧

```json
// 伪装 Gadget 名称和特征
{
    "interaction": {
        "type": "listen",
        "address": "127.0.0.1",
        "port": 27042
    },
    "module": {
        "name": "libnative-lib.so",  // 伪装为常见 SO 名
    }
}
```

### 5.4 结合 Runtime.exec 注入

对于无法直接修改 APK 的场景，可以通过系统级注入：

```bash
# 使用 ptrace 方式注入（需要 root）
# 或通过 Zygote 注入 - 在应用 fork 时注入 Gadget
```

## 6. Gadget 反检测对抗

| 检测方式 | Gadget 应对策略 |
|:---------|:---------------|
| **扫描 /proc/self/maps** | 重命名 Gadget SO 文件名 |
| **检测 Frida 端口** | 使用非标准端口或 script 模式 |
| **检测 frida-server 进程** | Gadget 以内嵌 SO 运行，无独立进程 |
| **检测 Java 层特征** | 避免使用 Java.perform 等特征明显的 API |
| **检测 Native 函数** | 编译时 Stripped（去除符号表） |

**重命名 Gadget SO 的最佳实践：**

```bash
# 将 frida-gadget.so 重命名为类似 App 自身 SO 的名称
# 例如 App 有 libnative-lib.so，可以改为：
cp frida-gadget.so lib/arm64-v8a/libimage-util.so
# 并同步修改配置中的 module name
```

## 7. 完整实战：重打包集成 Gadget

### 7.1 使用脚本自动化

```bash
#!/bin/bash
# patch_apk.sh — 自动化 Gadget 集成脚本

APK_PATH=$1
GADGET_PATH=$2
OUTPUT_PATH="${APK_PATH%.*}_patched.apk"
WORK_DIR="/tmp/apk_patch_$$"

# 1. 解压 APK
apktool d "$APK_PATH" -o "$WORK_DIR" -f

# 2. 复制 Gadget
mkdir -p "$WORK_DIR/lib/arm64-v8a"
cp "$GADGET_PATH" "$WORK_DIR/lib/arm64-v8a/libfrida-gadget.so"

# 3. 创建配置文件
mkdir -p "$WORK_DIR/assets"
cat > "$WORK_DIR/assets/frida-gadget.config.json" << 'EOF'
{
    "interaction": {
        "type": "listen",
        "address": "127.0.0.1",
        "port": 27042
    }
}
EOF

# 4. 修改 AndroidManifest.xml（如果需要）
# 添加 android:extractNativeLibs="true"

# 5. 重打包
apktool b "$WORK_DIR" -o "$OUTPUT_PATH"

# 6. 签名
jarsigner -keystore ~/.android/debug.keystore \
    -storepass android -keypass android \
    -sigalg SHA1withRSA -digestalg SHA1 \
    "$OUTPUT_PATH" androiddebugkey

# 7. 清理
rm -rf "$WORK_DIR"

echo "[+] Patched APK: $OUTPUT_PATH"
```

### 7.2 验证集成

```bash
# 1. 安装修补后的 APK
adb install -r target_patched.apk

# 2. 启动 App
adb shell am start -n com.example.app/.MainActivity

# 3. 验证 Gadget 是否运行
# listen 模式：
adb forward tcp:27042 tcp:27042
frida-ps -H 127.0.0.1:27042

# 应该看到目标 App 进程
```

## 8. 注意事项

| 注意事项 | 说明 |
|:--------|:----|
| **APK 大小** | Gadget SO 约 5-10MB，会增加 APK 体积 |
| **权限问题** | Gadget 随 App 运行，权限与 App 一致 |
| **网络隔离** | listen 模式需要网络端口，部分 App 可能有网络限制 |
| **多架构** | 需要为每种 CPU 架构准备对应的 Gadget SO |
| **签名校验** | 部分 App 有签名校验，重打包后可能闪退 |
| **稳定性** | Gadget 可能被 App 内部的稳定性检测触发 crash |
| **法律合规** | 仅用于授权的安全测试和学习研究 |

## 小结

- **Frida Gadget** 是 Frida 的 SO 形态，可以嵌入 APK 实现免 root 注入
- **两种模式**：`listen` 模式用于交互式调试，`script` 模式用于自动化运行
- **配置灵活**：通过 `frida-gadget.config.json` 控制 Gadget 行为
- **反检测**：通过重命名 SO、伪装模块名称、使用非标准端口等方式降低被检测风险
- 重打包 + Gadget 是免 root 场景下最实用的 Frida 部署方案

> **参考源文件**：Frida Gadget 官方文档；`awesomeFrida` 项目中的相关实践示例。
