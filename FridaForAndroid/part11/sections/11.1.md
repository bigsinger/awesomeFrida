# 11.1 Stalker：CPU指令级跟踪

> 核心要点：Stalker 是 Frida 内置的代码追踪引擎，允许在 CPU 指令级别监控目标程序的执行流。结合 ZenTracer.js 的封装思路，可以实现对特定类的所有方法调用进行全量指令级追踪。

## 1. Stalker 核心原理

Stalker（原名 "Stalker"）是 Frida 最强大的功能之一。它在目标进程内部实时插桩 ARM64/ARM32 指令，实现无侵入的指令级监控。

**工作原理：**

```
Stalker 启动
    ↓
Frida 在目标进程中分配一段内存用于代码缓存
    ↓
当目标线程执行到被追踪的代码区域时：
    ├── Stalker 拦截 CPU 执行流
    ├── 将原始指令复制到缓存区
    ├── 在关键指令前后插入追踪指令（callbacks）
    └── 修改 PC 寄存器指向缓存区
    ↓
目标线程在缓存区执行插桩后的代码
    ↓
每次执行到追踪点时触发回调 → 输出寄存器状态/内存信息
```

### 1.1 Stalker API 核心方法

```javascript
// 启动 Stalker 追踪
Stalker.follow(threadId, {
    events: {
        call: true,     // 追踪 call 指令
        ret: true,      // 追踪 ret 指令
        exec: true      // 追踪所有执行的代码块
    },
    transform: function(iterator) {
        // 对每个代码块进行转换
        var instruction = iterator.next();
        while (instruction) {
            // 分析并可选地修改指令
            iterator.keep();  // 保留原始指令
            instruction = iterator.next();
        }
    }
});

// 停止追踪
Stalker.unfollow(threadId);

// 垃圾回收，释放 Stalker 占用的缓存
Stalker.garbageCollect();
```

## 2. ZenTracer.js 追踪框架分析

> **引用源文件**：`awesomeFrida/ZenTracer.js`（完整117行代码）

ZenTracer.js 不是完整的 Stalker 脚本，而是一个**类追踪封装框架**。它通过 `Java.enumerateLoadedClasses` 扫描已加载的类，根据正则匹配自动 Hook 所有方法，实现批量追踪的效果。

### 2.1 通信协议（第1-23行）

```javascript
// 引用：awesomeFrida/ZenTracer.js 第1-7行
function log(text) {
    var packet = {
        'cmd': 'log',
        'data': text
    };
    send("ZenTracer:::" + JSON.stringify(packet))
}
```

ZenTracer 使用自定义的 JSON 通信协议，通过 `send()` 向 Python 客户端发送格式化的追踪数据。数据包分为两种类型：

| 命令 | 作用 | 数据格式 |
|:---:|:---|:---|
| `log` | 输出日志信息 | `{"cmd":"log","data":text}` |
| `enter` | 方法进入事件 | `{"cmd":"enter","data":[tid,tname,cls,method,args]}` |
| `exit` | 方法退出事件 | `{"cmd":"exit","data":[tid,retval]}` |

### 2.2 线程信息获取（第25-33行）

```javascript
// 引用：awesomeFrida/ZenTracer.js 第25-33行
function getTid() {
    var Thread = Java.use("java.lang.Thread")
    return Thread.currentThread().getId();
}

function getTName() {
    var Thread = Java.use("java.lang.Thread")
    return Thread.currentThread().getName();
}
```

通过 Hook java.lang.Thread 获取当前线程 ID 和线程名，实现多线程环境下的调用追踪区分。

### 2.3 自动类追踪（第35-69行）

```javascript
// 引用：awesomeFrida/ZenTracer.js 第35-68行
function traceClass(clsname) {
    try {
        var target = Java.use(clsname);
        var methods = target.class.getDeclaredMethods();
        methods.forEach(function (method) {
            var methodName = method.getName();
            var overloads = target[methodName].overloads;
            overloads.forEach(function (overload) {
                var proto = "(";
                overload.argumentTypes.forEach(function (type) {
                    proto += type.className + ", ";
                });
                if (proto.length > 1) {
                    proto = proto.substr(0, proto.length - 2);
                }
                proto += ")";
                log("hooking: " + clsname + "." + methodName + proto);
                overload.implementation = function () {
                    var args = [];
                    var tid = getTid();
                    var tName = getTName();
                    for (var j = 0; j < arguments.length; j++) {
                        args[j] = arguments[j] + ""
                    }
                    enter(tid, tName, clsname, methodName + proto, args);
                    var retval = this[methodName].apply(this, arguments);
                    exit(tid, "" + retval);
                    return retval;
                }
            });
        });
    } catch (e) {
        log("'" + clsname + "' hook fail: " + e)
    }
}
```

`traceClass()` 函数是 ZenTracer 的核心：

1. 通过 `Java.use()` 定位目标类
2. 使用 `class.getDeclaredMethods()` 枚举所有声明的方法
3. 遍历每个方法的所有重载（overloads）
4. 构建参数类型签名 `proto`
5. 替换 `implementation`：在方法进入时调用 `enter()`，退出时调用 `exit()`

### 2.4 类匹配引擎（第71-84行）

```javascript
// 引用：awesomeFrida/ZenTracer.js 第71-84行
function match(ex, text) {
    if (ex[1] == ':') {
        var mode = ex[0];
        if (mode == 'E') {
            ex = ex.substr(2, ex.length - 2);
            return ex == text;
        } else if (mode == 'M') {
            ex = ex.substr(2, ex.length - 2);
        } else {
            log("Unknown match mode: " + mode);
        }
    }
    return text.match(ex)
}
```

匹配引擎支持两种模式：
- `E:` — 精确匹配（Equal）
- `M:` — 正则匹配（Match）

### 2.5 主流程：按规则扫描与追踪（第86-117行）

```javascript
// 引用：awesomeFrida/ZenTracer.js 第86-117行
if (Java.available) {
    Java.perform(function () {
        log('ZenTracer Start...');
        var matchRegEx = { MATCHREGEX };
        var blackRegEx = { BLACKREGEX };
        Java.enumerateLoadedClasses({
            onMatch: function (aClass) {
                for (var index in matchRegEx) {
                    if (match(matchRegEx[index], aClass)) {
                        var is_black = false;
                        for (var i in blackRegEx) {
                            if (match(blackRegEx[i], aClass)) {
                                is_black = true;
                                log(aClass + "' black by '" + blackRegEx[i] + "'");
                                break;
                            }
                        }
                        if (is_black) {
                            break;
                        }
                        log(aClass + "' match by '" + matchRegEx[index] + "'");
                        traceClass(aClass);
                    }
                }
            },
            onComplete: function () {
                log("Complete.");
            }
        });
    });
}
```

整体流程：
1. 定义匹配规则（`MATCHREGEX`）和黑名单规则（`BLACKREGEX`）
2. `Java.enumerateLoadedClasses` 枚举所有已加载的类
3. 对每个类，检查是否匹配任一规则
4. 若匹配且不在黑名单中，调用 `traceClass()` 自动 Hook

> **注**：`MATCHREGEX` 和 `BLACKREGEX` 是占位符，实际使用时由 Python 客户端在注入前替换为具体的正则表达式。

## 3. 结合 Stalker 实现指令级追踪

ZenTracer 实现了**方法级别的追踪**。如果需要更细粒度的**指令级追踪**，可以用 Stalker 配合实现：

```javascript
// 在 ZenTracer 的 enter/exit 中集成 Stalker
function enter(tid, tname, cls, method, args) {
    // 方法进入时启动 Stalker
    Stalker.follow(tid, {
        events: {
            call: true,
            ret: true
        },
        transform: function(iterator) {
            var instruction;
            while ((instruction = iterator.next()) !== null) {
                iterator.keep();
                // 记录特殊指令（如 BL/jump 到关键函数）
                if (instruction.mnemonic === 'bl' ||
                    instruction.mnemonic === 'b') {
                    console.log(
                        `[Stalker] ${instruction.address} ` +
                        `${instruction.mnemonic} ${instruction.opStr}`
                    );
                }
            }
        }
    });
}

function exit(tid, retval) {
    // 方法退出时停止 Stalker，避免性能过度消耗
    Stalker.unfollow(tid);
}
```

## 4. Stalker 性能优化策略

| 策略 | 说明 | 代码示例 |
|:---:|:---|:---|
| **区域限制** | 只追踪特定函数地址范围，避免全量追踪 | `if (addr < start \|\| addr > end) { iterator.keep(); }` |
| **事件过滤** | 只关注 call/ret 事件，忽略普通指令 | `events: { call: true, ret: true }` |
| **快速解绑** | 追踪到目标后立即 unfollow | `Stalker.unfollow(tid)` |
| **缓存管理** | 定期调用 garbageCollect 释放缓存 | `Stalker.garbageCollect()` |
| **线程选择** | 只追踪感兴趣的线程 | `Stalker.follow(specificTid)` |

## 5. 实战：Hook 指定类的所有方法

```bash
# 使用 ZenTracer 追踪 javax.crypto 包下所有类
frida -U -l ZenTracer.js -f com.example.app --no-pause
```

Python 客户端示例：

```python
import frida
import json

def on_message(message, data):
    if message['type'] == 'send':
        payload = message['payload']
        if payload.startswith('ZenTracer:::'):
            packet = json.loads(payload[12:])
            cmd = packet['cmd']
            if cmd == 'log':
                print(f"[LOG] {packet['data']}")
            elif cmd == 'enter':
                tid, tname, cls, method, args = packet['data']
                print(f"[ENTER] [{tname}({tid})] {cls}.{method}")
            elif cmd == 'exit':
                tid, retval = packet['data']
                print(f"[EXIT] tid={tid}, retval={retval}")

device = frida.get_usb_device()
session = device.attach("com.example.app")

# 替换 MATCHREGEX 和 BLACKREGEX
script_content = open("ZenTracer.js").read()
script_content = script_content.replace(
    '{ MATCHREGEX }',
    json.dumps(['javax.crypto.*', 'java.security.*'])
)
script_content = script_content.replace(
    '{ BLACKREGEX }',
    json.dumps([])
)

script = session.create_script(script_content)
script.on("message", on_message)
script.load()
input()
```

## 小结

- **ZenTracer.js** 提供了基于正则匹配的自动类追踪框架，核心是 `traceClass()` 的自动 Hook + `match()` 的灵活匹配
- **Stalker** 是 Frida 的指令级追踪引擎，可实现比方法级更细粒度的追踪
- 实际使用中，通常将 ZenTracer 的类追踪与 Stalker 的指令追踪结合使用：先定位目标方法，再对关键方法开启 Stalker 指令追踪

> **参考源文件**：`awesomeFrida/ZenTracer.js`（117行）完整实现了基于 `Java.enumerateLoadedClasses` 的自动类追踪框架。
