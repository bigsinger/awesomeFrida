# 11.6 Bitmap 图片解密

> 核心要点：Android 应用常对网络传输的图片进行加密，在解码前再解密。通过 Hook `BitmapFactory.decodeByteArray` 截获解码前的数据，结合 Python 自动化解密框架，可以完整还原加密图片。

## 1. BitmapFactory 解码流程

Android 加载网络图片的典型流程：

```
网络请求
    ↓
获取加密的图片字节数据
    ↓
解密数据（AES / XOR / 自定义算法）
    ↓
BitmapFactory.decodeByteArray(解密后的数据, offset, length, opts)
    ↓                          ↑
    └── Hook 此处的 data 参数即可获取解码前的原始图片数据
Bitmap 对象（可用于显示）
```

**关键 Hook 点**：`BitmapFactory.decodeByteArray(byte[] data, int offset, int length, Options opts)` 的第一个参数 `data` 就是图片解码前的完整字节数据。

## 2. 四种 Bitmap 保存方案

> **引用源文件**：`Chap10/hookBitmap.js`（完整164行代码）

### 2.1 方案一：直接保存原始字节数据（saveBitmap_1）

```javascript
// 引用：Chap10/hookBitmap.js 第9-34行
function saveBitmap_1() {
    Java.perform(function() {
        Java.use('android.graphics.BitmapFactory').decodeByteArray
            .overload('[B', 'int', 'int', 'android.graphics.BitmapFactory$Options')
            .implementation = function(data, offset, length, opts) {
            var result = this.decodeByteArray(data, offset, length, opts);
            var ByteString = Java.use("com.android.okhttp.okio.ByteString");
            console.log("data is =>", ByteString.of(data).hex());
            console.log("data is coming!");
            var path = '/sdcard/Download/tmp/' + guid() + '.jpg';
            console.log("path is =>", path);
            var f = Java.use("java.io.File").$new(path);
            var fos = Java.use("java.io.FileOutputStream").$new(f);
            fos.write(data);
            fos.close();
            return result;
        }
    });
}
```

**原理**：直接将 `decodeByteArray` 接收到的 `data` 字节数组写入文件。如果图片是加密的，保存的是加密数据；如果是明文图片，保存的就是原始图片。

**适用场景**：图片未经加密，直接以原始格式传输。

### 2.2 方案二：使用 Bitmap.compress 保存（saveBitmap_2）

```javascript
// 引用：Chap10/hookBitmap.js 第35-68行
function saveBitmap_2() {
    Java.perform(function() {
        Java.use('android.graphics.BitmapFactory').decodeByteArray
            .overload('[B', 'int', 'int', 'android.graphics.BitmapFactory$Options')
            .implementation = function(data, offset, length, opts) {
            var result = this.decodeByteArray(data, offset, length, opts);
            var path = '/sdcard/Download/tmp/' + guid() + '.jpg';
            console.log("path is =>", path);
            var f = Java.use("java.io.File").$new(path);
            var fos = Java.use("java.io.FileOutputStream").$new(f);
            result.compress(
                Java.use("android.graphics.Bitmap$CompressFormat").JPEG.value,
                100, fos
            );
            fos.flush();
            fos.close();
            return result;
        }
    });
}
```

**原理**：先让 BitmapFactory 完成解码得到 `result`（Bitmap 对象），然后调用 `result.compress()` 将 Bitmap 重新压缩成 JPEG 文件。

**优势**：即使原始数据是加密的，只要 App 在 `decodeByteArray` 之前已经解密，result 就是正常的 Bitmap。

### 2.3 方案三：Runnable 子线程保存（saveBitmap_3）

```javascript
// 引用：Chap10/hookBitmap.js 第71-117行
function saveBitmap_3() {
    Java.perform(function() {
        var Runnable = Java.use("java.lang.Runnable");
        var saveImg = Java.registerClass({
            name: "com.roysue.runnable",
            implements: [Runnable],
            fields: {
                bm: "android.graphics.Bitmap",
            },
            methods: {
                $init: [{
                    returnType: "void",
                    argumentTypes: ["android.graphics.Bitmap"],
                    implementation: function(bitmap) {
                        this.bm.value = bitmap;
                    }
                }],
                run: function() {
                    var path = "/sdcard/Download/tmp/" + guid() + ".jpg";
                    console.log("path=> ", path);
                    var file = Java.use("java.io.File").$new(path);
                    var fos = Java.use("java.io.FileOutputStream").$new(file);
                    this.bm.value.compress(
                        Java.use("android.graphics.Bitmap$CompressFormat").JPEG.value,
                        100, fos
                    );
                    console.log("success!");
                    fos.flush();
                    fos.close();
                }
            }
        });

        Java.use('android.graphics.BitmapFactory').decodeByteArray
            .overload('[B', 'int', 'int', 'android.graphics.BitmapFactory$Options')
            .implementation = function(data, offset, length, opts) {
            var result = this.decodeByteArray(data, offset, length, opts);
            var runable = saveImg.$new(result);
            runable.run();
            return result;
        }
    });
}
```

**原理**：使用 `Java.registerClass` 动态创建 Runnable 类（详见 11.2 节），将 Bitmap 通过字段传递到 Runnable 的 `run()` 方法中保存。

**优势**：使用子线程执行 IO 操作，不阻塞 UI 线程。这是最推荐的方案。

### 2.4 方案四：通过 send 发送到 Python 客户端（saveBitmap_4）

```javascript
// 引用：Chap10/hookBitmap.js 第118-128行
function saveBitmap_4() {
    Java.perform(function() {
        Java.use('android.graphics.BitmapFactory').decodeByteArray
            .overload('[B', 'int', 'int', 'android.graphics.BitmapFactory$Options')
            .implementation = function(data, offset, length, opts) {
            var result = this.decodeByteArray(data, offset, length, opts);
            send(data);     // 将字节数组发送到 Python 端
            return result;
        }
    });
}
```

**原理**：使用 Frida 的 `send()` 将字节数组发送到 Python 客户端，由 Python 端负责解密和保存。

**优势**：
- 解密逻辑在 PC 端执行，不增加 App 运行时负担
- Python 端可以灵活处理各类加密算法
- 便于批量处理和数据管理

## 3. getKey() 密钥提取

```javascript
// 引用：Chap10/hookBitmap.js 第129-137行
function getKey() {
    Java.perform(function() {
        var CipherClient = Java.use('net.idik.lib.cipher.so.CipherClient');
        var key = CipherClient.decodeImgKey();
        var iv = CipherClient.decodeImgIv();
        console.log(key, iv);
    });
}
```

对于使用 `lib-cipher-so` 库加密图片的应用，`CipherClient` 类提供了 `decodeImgKey()` 和 `decodeImgIv()` 方法。Hook 并主动调用这两个方法即可获取 AES 密钥和 IV。

**典型输出**：
```
key: svOEKGb5WD0ezmHE4FXCVQ==
iv: 4B7eYzHTevzHvgVZfWVNIg==
```

## 4. hookEncodedBuffer() 加密数据截获

```javascript
// 引用：Chap10/hookBitmap.js 第138-158行
function hookEncodedBuffer() {
    Java.perform(function() {
        Java.use("com.ilulutv.fulao2.other.i.b").a
            .overload('java.nio.ByteBuffer').implementation = function(obj) {
            var result = this.a(obj);
            send(result);   // 将解密后的数据发送到 Python 端
            return result;
        }
    });
}
```

这个函数演示了针对特定应用的加密数据截获场景：
1. 目标类：`com.ilulutv.fulao2.other.i.b`
2. 目标方法：`a(ByteBuffer)` — 这是一个解密方法，输入加密的 ByteBuffer，输出解密后的数据
3. 将解密后的数据通过 `send()` 发送到 Python 客户端

## 5. saveBitmap.py Python 解密框架

> **引用源文件**：`Chap10/saveBitmap.py`（完整63行代码）

```python
# 引用：Chap10/saveBitmap.py（完整63行代码）
import frida
import json
import time
import uuid
import base64
from Crypto.Cipher import AES

def IMGdecrypt(bytearray):
    imgkey = base64.decodebytes(
        bytes("svOEKGb5WD0ezmHE4FXCVQ==", encoding='utf8'))
    imgiv = base64.decodebytes(
        bytes("4B7eYzHTevzHvgVZfWVNIg==", encoding='utf8'))
    
    cipher = AES.new(imgkey, AES.MODE_CBC, imgiv)
    msg = cipher.decrypt(bytearray)
    def unpad(s): return s[0:-s[-1]]
    return unpad(msg)


def my_message_handler(message, payload):
    if message["type"] == "send":
        image = message["payload"]
        intArr = []
        for m in image:
            ival = int(m)
            if ival < 0:
                ival += 256
            intArr.append(ival)
        bs = bytes(intArr)

        bs = IMGdecrypt(bs)  # 解密
        
        fileName = "/root/Chap10/tmp-5/" + str(uuid.uuid1()) + ".jpg"
        print('path is ', fileName)
        f = open(fileName, 'wb')
        f.write(bs)
        f.close()


device = frida.get_usb_device()
target = device.get_frontmost_application()
session = device.attach(target.pid)

with open("hookBitmap.js") as f:
    script = session.create_script(f.read())

script.on("message", my_message_handler)
script.load()

input()
```

### 5.1 框架核心流程

```
Frida 脚本（hookBitmap.js）
    ↓ saveBitmap_4() 或 hookEncodedBuffer()
send(加密数据) ────────→ Python 客户端
                            ↓
                    my_message_handler 接收数据
                            ↓
                    将 Java byte[] 转换为 Python bytes
                            ↓
                    IMGdecrypt() AES-CBC 解密
                            ↓
                    写入文件 /root/Chap10/tmp-5/uuid.jpg
```

### 5.2 关键函数解析

```python
# Java byte[] → Python bytes 转换
# Java byte 范围是 -128~127，Python byte 范围是 0~255
intArr = []
for m in image:
    ival = int(m)
    if ival < 0:
        ival += 256  # Java signed → Python unsigned
    intArr.append(ival)
bs = bytes(intArr)
```

```python
# AES-CBC 解密 + PKCS7 Unpad
def IMGdecrypt(bytearray):
    imgkey = base64.decodebytes(bytes("key...", encoding='utf8'))
```

```bash

adb shell mkdir -p /sdcard/Download/tmp/

# 2. 根据场景选择合适的 saveBitmap 方案
```

## 7. 四种方案对比

| 方案 | 保存位置 | 是否需解密 | 优势 | 劣势 |
|:---:|:--------:|:--------:|:---|:---|
| **saveBitmap_1** | 手机 | 否 | 简单直接 | 加密图片无法查看 |
| **saveBitmap_2** | 手机 | 否（App已解密） | 可直接查看图片 | Bitmap.compress 有损 |
| **saveBitmap_3** | 手机 | 否（App已解密） | 不阻塞 UI，推荐 | 代码较复杂 |
| **saveBitmap_4** | PC | 是 | 灵活的解密逻辑 | 需网络传输大量数据 |

## 小结

- **`hookBitmap.js`** 提供了 4 种 Bitmap 保存方案，覆盖了从简单截获到复杂解密的全部场景
- **方案三（saveBitmap_3）** 结合了 `Java.registerClass` 创建 Runnable 类 + Bitmap.compress 子线程保存，是推荐的通用方案
- **方案四（saveBitmap_4 + saveBitmap.py）** 实现了 Frida + Python 的协同工作模式：Frida 发送原始数据，Python 端负责解密和存储
- **AES 密钥提取** 可通过 Hook `CipherClient.decodeImgKey()` 获取，也可结合 11.3 节的加密追踪框架自动化提取

> **参考源文件**：`Chap10/hookBitmap.js`（164行）提供了四种 Bitmap 保存方案及密钥提取函数；`Chap10/saveBitmap.py`（63行）提供了完整的 Python 自动化解密框架。
