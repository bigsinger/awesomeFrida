# 2.2 Spawn 与 Attach 两种注入模式

## 概述

Frida 提供两种主要的进程注入模式：**Attach（附加）** 和 **Spawn（启动）**。理解它们的区别是正确编写 Frida 脚本的基础。

| 特征 | Attach | Spawn |
|------|--------|-------|
| 时机 | App 已运行后注入 | App 启动时注入 |
| 命令 | `frida -U com.xxx` | `frida -U -f com.xxx` |
| 能否 Hook 启动逻辑 | ❌ 可能错过 | ✅ 完整覆盖 |
| 多进程场景 | ✅ 可以 | ✅ 支持 |
| 最常用场景 | 运行时调试 | 分析启动流程 |
| 暂停控制 | 不可暂停 | 默认暂停，`--no-pause` 取消 |

## Attach 模式

### 用法

```bash
# 先启动 App，再附加脚本
frida -U com.roysue.demo02
frida -U com.roysue.demo02 -l script.js

# 按进程名匹配
frida -U -n demo02

# 按 PID 匹配
frida -U -p 1234
```

### Python 实现 Attach

```python
# 引用自 Chap04/loader.py 第 12-13 行（Attach 模式）
import frida

device = frida.get_usb_device()

# Attach 到已运行的进程
process = device.attach('com.roysue.demo02')
# 或使用 PID
# process = device.attach(1234)

print(f"[+] Attached to: {process}")
```

> **代码来源**：`Chap04/loader.py` 第 12-13 行，展示了 `device.attach()` 的基本用法。

### Attach 的特点

- ✅ **灵活**：随时可以注入，无需重启 App
- ✅ **快速**：注入过程几乎瞬时完成
- ❌ **可能错过早期逻辑**：App 启动时的初始化代码已在 Attach 前执行
- ✅ **多进程**：可以同时 Attach 到多个进程

## Spawn 模式

### 用法

```bash
# 启动 App 的同时注入脚本
frida -U -f com.roysue.demo02 -l script.js

# 不暂停执行（App 自动运行）
frida -U -f com.roysue.demo02 -l script.js --no-pause

# Spawn 后进入交互模式
frida -U -f com.roysue.demo02
```

### Python 实现 Spawn

```python
# 引用自 Chap04/loader.py 第 12-13 行（可适配 Spawn 模式）
import frida, sys

device = frida.get_usb_device()

# Spawn 模式：启动新进程
pid = device.spawn(['com.roysue.demo02'])
process = device.attach(pid)

# 加载脚本
with open('call.js') as f:
    jscode = f.read()
script = process.create_script(jscode)

script.on('message', on_message)
script.load()

# 恢复进程执行
device.resume(pid)

print(f"[+] Spawned and attached to PID: {pid}")
sys.stdin.read()
```

> **代码来源**：基于 `Chap04/loader.py` 第 12-20 行结构，适配为 Spawn 模式。

### Spawn 的暂停与恢复

Spawn 模式下，App 启动后默认 **暂停**，等待脚本加载：

```bash
# 1. 终端 1：启动 Spawn
frida -U -f com.roysue.demo02 -l script.js
# App 默认暂停，等待 %resume 命令

# 2. 在 frida 交互界面输入
%resume  # 恢复进程执行
```

Python 中对应：

```python
# Spawn 后默认暂停
pid = device.spawn(['com.roysue.demo02'])
# 加载脚本...
script.load()
# 恢复执行
device.resume(pid)
```

## 如何选择？

```python
# 场景判断逻辑（伪代码）
def choose_mode(app_scenario):
    if app_scenario == "需要分析启动流程":
        return "Spawn"   # 从 App.onCreate 开始 Hook
    elif app_scenario == "已启动，临时调试":
        return "Attach"  # 快速介入
    elif app_scenario == "反调试检测载入":
        return "Spawn"   # 在反调试执行前 Hook
    else:
        return "Attach"  # 默认使用 Attach
```

### 实战建议

| 场景 | 推荐模式 | 原因 |
|------|---------|------|
| 参数篡改 | Attach | 随时可以测试不同输入 |
| 启动协议分析 | Spawn | 不遗漏任何调用 |
| SSL Pinning 绕过 | Spawn | 需要在 SSL 初始化前 Hook |
| 日常调试 | Attach | 最快捷 |
| 脱壳 | Spawn | 从加载 DEX 开始追踪 |

## 完整对比运行示例

```bash
# Attach 模式
frida -U com.roysue.demo02 -l hello_world.js

# Spawn 模式
frida -U -f com.roysue.demo02 -l hello_world.js --no-pause
```

两行命令的输出应该完全一致，但背后的执行时机完全不同：

- **Attach**：在 `onCreate` 等初始化完成后注入
- **Spawn**：从进程创建开始就控制执行流

## 小结

- **Attach**：附加到已有进程，灵活快捷
- **Spawn**：启动新进程，完整覆盖生命周期
- Python 中：`device.attach()` vs `device.spawn() + device.resume()`
- 特殊场景（脱壳、SSL Pinning）优先使用 Spawn
- 日常调试推荐 Attach
