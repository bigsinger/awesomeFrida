# 5.6 Objection 一键绕过 SSL Pinning

> **Objection** 是基于 Frida 的运行时移动安全探索框架。它封装了大量常用操作，包括一键绕过 SSL Pinning。对于 80% 的 App，Objection 的 `android sslpinning disable` 命令可以秒级完成绕过。

## 1. Objection 基础安装

```bash
# 使用 pip 安装
pip3 install objection

# 验证安装
objection version
```

## 2. 一键绕过 SSL Pinning

```bash
# 基本命令（自动附加进程）
objection -g com.roysue.targetapp explore

# 进入 objection 交互控制台后，输入：
android sslpinning disable
```

## 3. Objection 内部做了什么

`android sslpinning disable` 命令会 Hook 以下方法：

| 分类 | Hook 点 | 处理方式 |
|:---:|:---|:---|
| **CertificatePinner** | `okhttp3.CertificatePinner.check()` | 直接 return |
| **TrustManager** | `X509TrustManager.checkServerTrusted()` | 跳过校验 |
| **HostnameVerifier** | 各实现类的 `verify()` | 强制返回 true |
| **SSLContext** | `SSLContext.init()` | 替换 TrustManager |
| **HttpsURLConnection** | `setSSLSocketFactory()` | 阻止设置 |
| **HttpsURLConnection** | `setHostnameVerifier()` | 阻止设置 |
| **HttpsURLConnection** | `setDefaultHostnameVerifier()` | 阻止设置 |

> 这与我们在 5.5 节中手动编写的综合绕过脚本功能几乎一致。

## 4. 高级用法

### 4.1 指定绕过模块

```bash
# 只绕过 OkHttp
objection -g com.roysue.targetapp explore --startup-command "android sslpinning disable --okhttp"

# 只绕过 Android 原生
objection -g com.roysue.targetapp explore --startup-command "android sslpinning disable --native"

# 一次性注入多个命令
objection -g com.roysue.targetapp explore \
  --startup-command "android sslpinning disable" \
  --startup-command "android hooking watch class_method java.net.Socket.$init --dump-args"
```

### 4.2 结合 Spawn 模式

```bash
# 启动 App 时立即注入
objection -g com.roysue.targetapp explore --startup-command "android sslpinning disable"

# 或者在启动后延迟注入
objection -g com.roysue.targetapp explore
# 等 App 加载完成后输入
android sslpinning disable
```

### 4.3 配合代理使用

```bash
# 终端 1：启动 mitmproxy
mitmproxy -p 8888

# 终端 2：设置 Android 代理 + 注入 Objection
adb shell settings put global http_proxy 192.168.1.100:8888
objection -g com.roysue.targetapp explore --startup-command "android sslpinning disable"
```

## 5. 验证绕过是否成功

```bash
# 使用 objection 的 android hooking 命令验证
objection -g com.roysue.targetapp explore

# 查看 OkHttp 是否被 Hook
android hooking list classes

# 监控 Socket 连接
android hooking watch class_method java.net.Socket.$init --dump-args
```

## 6. Objection vs 手动 Frida 脚本

| 对比项 | Objection | 手动 Frida 脚本 |
|:---:|:---:|:---:|
| **使用复杂度** | ⭐ 极低（1 条命令） | ⭐⭐⭐ 需要编写 JS |
| **绕过覆盖度** | 80%（常见方案） | 100%（自定义） |
| **定制能力** | 低 | 高 |
| **调试信息** | 较少 | 丰富 |
| **混淆处理** | 有限 | 可手动适配 |
| **适用场景** | 快速验证、初步测试 | 深度逆向、对抗混淆 |

## 7. 常见问题

| 问题 | 原因 | 解决方案 |
|:---|:---|:---|
| **绕过后仍无法抓包** | App 使用了非标准 SSL 实现（如 BoringSSL） | 使用 5.4 节的 Native 层 Hook |
| **App 检测 Frida** | 存在反 Frida 检测 | 使用 Frida Gadget + 隐藏模块 |
| **Objection 版本过低** | 某些 SSL Pinning 方案未覆盖 | 更新 objection：`pip3 install -U objection` |
| **混淆后的 OkHttp** | 类名被混淆，Objection 无法识别 | 使用 6.1 节的 JustTrustMe Hook Finder |
| **双因素 SSL Pinning** | 同时使用 CertificatePinner + TrustManager | Objection 会同时绕过两者 |

## 8. 局限性

Objection 的 `android sslpinning disable` 并非万能的：

1. **对 BoringSSL 无效** — 6.2 节单独讲解
2. **对 Chromium 网络栈无效** — 6.3 节处理
3. **对自定义 SSL 实现无效** — 需要手动逆向
4. **对 Native 层证书绑定无效** — 需要 Hook Native 函数

> **引用**：Objection 的 SSL Pinning 绕过功能是对 5.5 节手动绕过方案的自动化封装。对于更复杂的情况，请参考第 6 章的 JustTrustMe（6.1）、BoringSSL（6.2）和 r0capture（6.4）方案。
