# 8.4 Hook未导出函数：基址+偏移

> 核心要点：当我们需要 Hook 的函数没有导出符号（被 strip、内联函数、动态注册的 JNI 函数）时，需要利用 SO 基址 + 函数偏移量来定位。

## 1. 为什么需要偏移 Hook？

```
导出函数（有符号）         未导出函数（无符号）
    │                           │
    ├─ 编译时生成                 ├─ 被 strip 工具删除
    ├─ 在 .dynsym 中              ├─ 本来就是 static 函数
    ├─ 可以被 dlsym 查到           ├─ 没有链接属性（LOCAL 符号）
    ├─ 可直接用名称定位            ├─ 只能通过基址+偏移定位
    └─ Module.findExportByName     └─ Module.findBaseAddress + add(offset)
```

**需要偏移 Hook 的典型场景：**

1. SO 被 strip 优化（减少文件大小、隐藏符号）
2. `static` 函数（文件作用域，不导出）
3. 通过 `RegisterNatives` 动态注册的 JNI 函数（名称可能不包含 Java 包路径）
4. 加固 SO 的入口函数和内部逻辑函数

## 2. 偏移 Hook 的核心 API

### 2.1 Module.findBaseAddress()

```javascript
// 获取模块的基址
var base = Module.findBaseAddress("libnative-lib.so");
console.log("[*] Base address: " + base);

// 与 Process.findModuleByName 返回 Module 对象不同，
// findBaseAddress 直接返回 NativePointer

// 对比：
var mod = Process.findModuleByName("libnative-lib.so");
console.log("[*] Base from Process: " + mod.base);
// mod.base 和 findBaseAddress 的返回值相同
```

### 2.2 偏移计算与定位

```javascript
// 基址 + 偏移 = 目标函数的绝对地址
var base = Module.findBaseAddress("libnative-lib.so");
var offset = 0xF444;  // 从 IDA Pro 得到的函数偏移
var targetAddr = base.add(offset);

console.log("[*] Function at: " + targetAddr);
// 输出示例：[*] Function at: 0x7bcf0744

// 反过来：已知绝对地址，计算偏移
var unknownFunc = ptr("0x7bcf0744");
var calculatedOffset = unknownFunc.sub(base);
console.log("[*] Offset: 0x" + calculatedOffset.toString(16));
// 输出示例：[*] Offset: 0xf444
```

## 3. 完整代码分析：hookNative.js 第13-36行

```javascript
// 引用：Chap11/hookNative.js 第13-36行
function hook_native3(){
    // 1. 获取 SO 基址
    var libnative_addr = Module.findBaseAddress('libnative-lib.so');
    console.log("libnative_addr is => ", libnative_addr);
    
    // 2. 通过偏移定位函数
    var stringfromJNI3 = libnative_addr.add(0xf444);
    console.log("stringfromJNI3 address is =>", stringfromJNI3);

    // 3. Hook 该地址
    Interceptor.attach(stringfromJNI3, {
        onEnter: function(args){
            console.log("jnienv pointer =>", args[0]);
            console.log("jobj pointer =>", args[1]);
        },
        onLeave: function(retval){
            console.log("retval is =>", 
                Java.vm.getEnv().getStringUtfChars(retval, null).readCString());
            console.log("=================");
        }
    });
}

function main(){
    hook_native3()
}
setImmediate(main)
```

**执行流程：**

```
Module.findBaseAddress('libnative-lib.so')
    ↓
返回基址，例如 0x7bcf0000
    ↓
base.add(0xf444)
    ↓
目标地址 = 0x7bcf0000 + 0xf444 = 0x7bcf0744
    ↓
Interceptor.attach(0x7bcf0744, {...})
    ↓
当 stringFromJNI3 被调用时，onEnter 触发
```

## 4. 如何获取函数偏移

### 4.1 通过 IDA Pro 分析

```bash
# 1. 将 SO 文件加载到 IDA Pro
# 2. 使用 IDA 的函数列表（Functions window）或导航视图
# 3. 找到目标函数，记录其偏移地址
# 4. 偏移 = 函数地址 - SO 加载基址（通常是 0x0）
```

### 4.2 通过 readelf 查找

```bash
# 从符号表中获取偏移（如果有符号的话）
readelf -s libnative-lib.so | grep stringFromJNI3

# 输出：
# 3: 00000000000006c4   84 FUNC  GLOBAL DEFAULT  11 stringFromJNI3
# 偏移就是 0x6c4

# 对于无符号的内部函数，readelf 无法直接获取
# 需要配合反汇编工具
```

### 4.3 通过 Frida 脚本动态发现

```javascript
// 在 IDA 中已知某个函数的偏移
// 可以通过 Frida 验证该偏移是否正确

function verifyOffset(moduleName, offset, expectedBehavior) {
    var mod = Process.findModuleByName(moduleName);
    if (!mod) return;
    
    var addr = mod.base.add(offset);
    console.log("[*] Testing function at " + moduleName + "+0x" + 
                offset.toString(16) + " = " + addr);
    
    // 尝试 Hook 并观察行为
    Interceptor.attach(addr, {
        onEnter: function(args) {
            console.log("[+] Function at offset 0x" + offset.toString(16) + 
                       " called with " + args.length + " args");
            for (var i = 0; i < Math.min(args.length, 4); i++) {
                console.log("  arg[" + i + "] = " + args[i]);
            }
            
            // 如果发现这是我们要找的函数，设置全局标志
            if (expectedBehavior(args)) {
                console.log("[✅] This is the target function!");
                this.isTarget = true;
            }
        },
        onLeave: function(retval) {
            if (this.isTarget) {
                console.log("[+] Target returned: " + retval);
            }
        }
    });
}
```

## 5. 偏移与导出符号混合使用

```javascript
// 先尝试导出符号，失败则退回到偏移 Hook
function smart_hook(moduleName, exportName, offset, callbacks) {
    var addr = null;
    
    // 先尝试通过导出符号名查找
    if (exportName) {
        addr = Module.findExportByName(moduleName, exportName);
        if (addr) {
            console.log("[+] Found by export name: " + exportName);
        }
    }
    
    // 导出符号未找到，使用偏移
    if (!addr && offset !== undefined) {
        var mod = Process.findModuleByName(moduleName);
        if (mod) {
            addr = mod.base.add(offset);
            console.log("[+] Using offset 0x" + offset.toString(16));
        }
    }
    
    if (!addr) {
        console.log("[-] Cannot locate target function");
        return null;
    }
    
    return Interceptor.attach(addr, {
        onEnter: function(args) {
            console.log("[+] Entering " + (exportName || "func@0x" + offset.toString(16)));
            if (callbacks.onEnter) callbacks.onEnter.call(this, args);
        },
        onLeave: function(retval) {
            if (callbacks.onLeave) callbacks.onLeave.call(this, retval);
        }
    });
}

// 使用：先找符号，找不到用偏移
smart_hook("libnative-lib.so", null, 0xf444, {
    onEnter: function(args) {
        console.log("stringFromJNI3 called");
    },
    onLeave: function(retval) {
        console.log("stringFromJNI3 returned");
    }
});
```

## 6. 偏移表的生成与验证

```javascript
// 生成指定模块中所有可执行区域的偏移范围
// 这有助于确认一个偏移是否属于代码段
function findCodeOffsets(moduleName) {
    var mod = Process.findModuleByName(moduleName);
    if (!mod) return [];
    
    // 通过解析 ELF program headers 找到可执行段
    var base = mod.base;
    var e_phoff = Process.pointerSize === 8 ? 
        base.add(32).readU64() : base.add(28).readU32();
    var e_phnum = Process.pointerSize === 8 ?
        base.add(54).readU16() : base.add(44).readU16();
    var e_phentsize = Process.pointerSize === 8 ?
        base.add(56).readU16() : base.add(42).readU16();
    
    var codeSegments = [];
    for (var i = 0; i < e_phnum; i++) {
        var phdr = base.add(e_phoff + i * e_phentsize);
        var p_type = phdr.readU32();
        var p_flags = Process.pointerSize === 8 ?
            phdr.add(4).readU32() : phdr.add(24).readU32();
        var p_vaddr = Process.pointerSize === 8 ?
            phdr.add(16).readU64() : phdr.add(8).readU32();
        var p_memsz = Process.pointerSize === 8 ?
            phdr.add(40).readU64() : phdr.add(20).readU32();
        
        if (p_type === 1 && (p_flags & 1)) { // PT_LOAD + PF_X
            codeSegments.push({
                start: p_vaddr,
                end: p_vaddr + p_memsz,
                offset: phdr.add(8).readU32()  // p_offset
            });
            console.log("[*] Code segment: 0x" + p_vaddr.toString(16) + 
                       " - 0x" + (p_vaddr + p_memsz).toString(16));
        }
    }
    
    return codeSegments;
}
```

## 7. 实战：Hook 被 strip 的 SO

```javascript
// 某个 SO 被 strip，所有符号被删除
// 已知目标函数在偏移 0xABC0 处
function hook_stripped_so() {
    var mod = Process.findModuleByName("libtarget.so");
    if (!mod) {
        console.log("[-] Module not loaded yet");
        return;
    }
    
    // 先看看还有没有残留的导出符号
    var exports = mod.enumerateExports();
    console.log("[*] Exports after strip: " + exports.length);
    exports.forEach(function(exp) {
        console.log("  " + exp.name);
    });
    
    // 使用 IDA 分析得到关键函数偏移
    var keyFunctions = {
        "init_check":    0xABC0,
        "verify_license": 0xBE50,
        "decrypt_data":   0xD200
    };
    
    // 逐一 Hook
    Object.keys(keyFunctions).forEach(function(name) {
        var offset = keyFunctions[name];
        var addr = mod.base.add(offset);
        
        console.log("[+] Hooking " + name + " @ " + moduleName + "+0x" + 
                   offset.toString(16) + " = " + addr);
        
        Interceptor.attach(addr, {
            onEnter: function(args) {
                console.log("[*] " + name + " called");
            },
            onLeave: function(retval) {
                console.log("[*] " + name + " returned: " + retval);
                // 可以在这里修改返回值来绕过校验
                if (name === "verify_license") {
                    console.log("[!] Overriding verify_license result");
                    retval.replace(ptr(1)); // 返回成功
                }
            }
        });
    });
}
```

## 8. 使用 Frida Stalker 发现函数边界

当 IDA 分析不可用时，可以使用 Frida Stalker 跟踪执行流来发现函数边界：

```javascript
// 使用 Stalker 跟踪代码执行，发现函数入口
function findFunctionByTracing(mod, startOffset, duration_ms) {
    var startAddr = mod.base.add(startOffset);
    var visited = new Set();
    var entries = [];
    
    // 在 startAddr 安装 Stalker
    Stalker.follow({
        events: {
            call: true,  // 跟踪函数调用
            ret: false
        },
        onReceive: function(events) {
            // 简化为只记录未访问过的地址
            events.forEach(function(evt) {
                if (evt.type === 'call') {
                    var addr = evt.target;
                    var offset = addr.sub(mod.base);
                    
                    if (!visited.has(offset.toString())) {
                        visited.add(offset.toString());
                        entries.push({
                            address: addr,
                            offset: offset
                        });
                    }
                }
            });
        }
    });
    
    // 一段时间后停止跟踪
    setTimeout(function() {
        Stalker.unfollow();
        console.log("[*] Found " + entries.length + " function entries:");
        entries.forEach(function(e) {
            console.log("  0x" + e.offset.toString(16) + " " + e.address);
        });
    }, duration_ms || 5000);
}
```

## 9. 常见问题与排查

### 9.1 偏移不正确

```javascript
// 确认偏移是否正确
function verify_address(moduleName, offset) {
    var mod = Process.findModuleByName(moduleName);
    if (!mod) {
        console.log("[-] Module not found");
        return false;
    }
    
    var addr = mod.base.add(offset);
    
    // 检查地址是否在模块范围内
    var inRange = addr.compare(mod.base) >= 0 && 
                  addr.compare(mod.base.add(mod.size)) < 0;
    
    if (!inRange) {
        console.log("[-] Address out of module range!");
        return false;
    }
    
    // 检查该地址是否可执行
    try {
        // 尝试读取指令（ARM64 指令是4字节）
        var instruction = addr.readU32();
        console.log("[*] First instruction at target: 0x" + 
                   instruction.toString(16));
        return true;
    } catch (e) {
        console.log("[-] Cannot read memory at target address");
        return false;
    }
}
```

### 9.2 ASLR 变化

每次进程启动时，SO 的基址都会因 ASLR 而变化，但**偏移是固定的**。所以偏移 Hook 脚本可以跨进程运行：

```javascript
// ASLR 不影响偏移 Hook
// 每次运行时，基址可能不同：
// 第一次：base = 0x7bcf0000, target = 0x7bcf0000 + 0xf444 = 0x7bcf0744
// 第二次：base = 0x8a3d0000, target = 0x8a3d0000 + 0xf444 = 0x8a3d0744
// 偏移 0xf444 始终不变
```

## 总结

- **偏移 Hook** 适用于没有导出符号的目标函数，是 Native Hook 的进阶技术
- **核心公式**：`目标地址 = Module.findBaseAddress(模块名).add(偏移量)`
- **偏移来源**：IDA Pro 分析、readelf 符号表、Frida Stalker 动态发现
- **导出 vs 偏移**：先尝试导出符号（简单可靠），失败后再用偏移（需要逆向分析）
- **注意事项**：确认偏移在代码段范围内、验证指令对齐（ARM64 为4字节对齐）、不同版本的 SO 偏移可能变化
