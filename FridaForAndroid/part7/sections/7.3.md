# 7.3 JNI函数注册机制

> 核心要点：JNI（Java Native Interface）函数注册有两种方式——静态注册和动态注册。理解这两种机制及其异同，是编写和逆向 JNI 函数 Hook 脚本的基础。

## 1. JNI 函数注册概述

当 Java 代码调用 `native` 方法时，Java 虚拟机需要找到对应的 C/C++ 函数实现。这个查找过程就是 JNI 函数注册，有两种方式：

```
静态注册（命名约定）
    ↓
    编译器根据 Java_com_xxx_yyy 命名规则
    自动在符号表中生成对应符号
    ↓
    VM 通过 dlsym("Java_com_xxx_yyy") 查找

动态注册（RegisterNatives）
    ↓
    SO 中的 JNI_OnLoad 函数被 VM 调用
    ↓
    JNI_OnLoad 中调用 RegisterNatives
    手动绑定 Java native 方法 ↔ C 函数
```

## 2. 静态注册

### 2.1 命名规则

静态注册依赖 C 函数名遵循严格的命名规则：

```
Java_<包名>_<类名>_<方法名>
```

其中：
- 包名中的 `.` 替换为 `_`
- 包含 `_` 的方法名中的 `_` 替换为 `_1`
- 使用 `JNIEXPORT` 和 `JNICALL` 宏声明

### 2.2 代码示例

```cpp
// 引用：Chap11/r0so/app/src/main/cpp/native-lib.cpp 第16-31行
// 静态注册示例
extern "C" JNIEXPORT jstring JNICALL
Java_com_roysue_r0so_MainActivity_stringFromJNI(
        JNIEnv* env,
        jobject /* this */) {
    std::string hello = "Hello from C++ r0ysue";
    return env->NewStringUTF(hello.c_str());
}

extern "C" JNIEXPORT jstring JNICALL
Java_com_roysue_r0so_MainActivity_stringFromJNI2(
        JNIEnv* env,
        jobject /* this */) {
    std::string hello = "Hello from C++ stringFromJNI2 r0ysue ";
    return env->NewStringUTF(hello.c_str());
}
```

**函数名解析：**

```
Java_com_roysue_r0so_MainActivity_stringFromJNI
  │    │       │       │             │
  │    └───包名────┘   类名        方法名
  固定前缀
```

### 2.3 Java 对应代码

```java
// Java 端对应的 native 方法声明
package com.roysue.r0so;

public class MainActivity {
    // 对应 C 函数 Java_com_roysue_r0so_MainActivity_stringFromJNI
    public native String stringFromJNI();
    
    // 对应 C 函数 Java_com_roysue_r0so_MainActivity_stringFromJNI2
    public native String stringFromJNI2();
}
```

### 2.4 编译后的符号表查看

编译 SO 后，通过 `readelf` 查看导出符号：

```bash
# 查看 SO 的导出符号，确认静态注册的函数
readelf -s libnative-lib.so | grep Java_

# 输出：
#  1: 00000000000005f0  112 FUNC  GLOBAL DEFAULT  11 Java_com_roysue_r0so_MainActivity_stringFromJNI
#  2: 0000000000000660  100 FUNC  GLOBAL DEFAULT  11 Java_com_roysue_r0so_MainActivity_stringFromJNI2
```

这两个函数都在 `.dynsym` 中，意味着它们可以通过 `Module.findExportByName()` 或 `Module.getExportByName()` 直接定位。

### 2.5 静态注册的优缺点

| 优点 | 缺点 |
|------|------|
| 简单直接，无需额外代码 | 函数名冗长，不便于混淆 |
| 编译后自动导出，VM 自动查找 | 首次调用时需要符号查找，性能稍差 |
| 系统自动处理注册生命周期 | 无法在运行时动态增加/修改绑定 |
| 便于逆向分析（符号名包含包名和类名） | 加固场景下容易被静态分析定位 |

## 3. 动态注册

### 3.1 JNI_OnLoad 入口

动态注册的核心是 `JNI_OnLoad` 函数，它由 Java 虚拟机在 `dlopen` 返回后自动调用。SO 在此函数中通过 `RegisterNatives` API 手动绑定 Java native 方法与 C 函数。

```cpp
// 引用：Chap11/r0so/app/src/main/cpp/native-lib.cpp 第48-59行
jint JNI_OnLoad(JavaVM* vm, void* reserved)
{
    JNIEnv *env;
    vm->GetEnv((void**)&env, JNI_VERSION_1_6);
    
    // 定义 JNINativeMethod 数组
    JNINativeMethod methods[] = {
        {"sI3",                             // Java 方法名
         "()Ljava/lang/String;",            // 方法签名
         (void*)stringFromJNI3},           // C 函数指针
    };
    
    // 调用 RegisterNatives 注册
    env->RegisterNatives(
        env->FindClass("com/roysue/r0so/MainActivity"),  // 目标类
        methods,                            // JNINativeMethod 数组
        1);                                 // 注册方法数量
    
    return JNI_VERSION_1_6;
}
```

### 3.2 JNINativeMethod 结构体

```cpp
typedef struct {
    const char* name;       // Java native 方法名
    const char* signature;  // 方法签名（参数和返回值类型描述）
    void*       fnPtr;      // C 函数指针
} JNINativeMethod;
```

**方法签名格式：**

| 类型标识 | Java 类型 |
|---------|----------|
| `Z` | boolean |
| `B` | byte |
| `C` | char |
| `S` | short |
| `I` | int |
| `J` | long |
| `F` | float |
| `D` | double |
| `L包名/类名;` | 对象类型 |
| `[类型` | 数组类型 |

**方法签名示例：**

```
"()V"                          → void func()
"(I)V"                         → void func(int)
"(ILjava/lang/String;)V"       → void func(int, String)
"(Ljava/lang/String;)I"        → int func(String)
"([BII)I"                      → int func(byte[], int, int)
"()Ljava/lang/String;"         → String func()  ← sI3 的签名
```

### 3.3 动态注册的函数名在符号表中的表现

`stringFromJNI3` 没有使用 `Java_com_` 前缀命名，它在符号表中表现为普通的函数符号：

```bash
# 查看 stringFromJNI3 在符号表中的信息
readelf -s libnative-lib.so | grep stringFromJNI3

# 输出：
#  3: 00000000000006c4   84 FUNC  GLOBAL DEFAULT  11 stringFromJNI3
```

与静态注册的函数不同，`stringFromJNI3` 的函数名不包含包名和类名，这使得它通过 `Module.findExportByName("libnative-lib.so", "stringFromJNI3")` 查找时更为简洁。

### 3.4 动态注册的优缺点

| 优点 | 缺点 |
|------|------|
| 函数名可以任意，便于代码组织 | 需要额外实现 JNI_OnLoad |
| 可在运行时动态修改绑定（如加固） | 注册失败的调试难度更大 |
| 支持同一 Java 方法绑定不同 C 函数 | 需要显式管理注册生命周期 |
| 便于代码混淆（函数名可改为无意义字符） | 若 JNI_OnLoad 被 Hook 或跳过则无法注册 |

## 4. Frida Hook JNI_OnLoad

### 4.1 基本 Hook

```javascript
// 引用：awesomeFrida/JNI_OnLoad.js（第38-44行）
// Hook JNI_OnLoad
Interceptor.attach(jniOnLoad, {
    onEnter(args) {
        console.log("[Hooked] JNI_OnLoad 被调用");
    }
});
```

### 4.2 在 dlopen 后等待并 Hook

因为 `JNI_OnLoad` 在 `dlopen` 返回后才被调用，所以我们需要先 Hook `dlopen`，在目标库加载后设置 `JNI_OnLoad` 的 Hook：

```javascript
// 引用：awesomeFrida/JNI_OnLoad.js（完整代码69行）
const TARGET_LIB_NAME = "libmsaoaidsec.so";

function hook_JNI_OnLoad() {
    // 先尝试通过 findExportByName
    let jniOnLoad = Module.findExportByName(TARGET_LIB_NAME, "JNI_OnLoad");

    // 如果找不到，就遍历所有导出符号
    if (!jniOnLoad) {
        console.log("[Info] `JNI_OnLoad` 未导出，尝试遍历导出符号...");
        for (let symbol of module.enumerateSymbols()) {
            if (symbol.name.indexOf("JNI_OnLoad") >= 0) {
                jniOnLoad = symbol.address;
                console.log("[Success] 找到 JNI_OnLoad: ", jniOnLoad);
                break;
            }
        }
    }

    if (!jniOnLoad) {
        console.error("[Error] 未找到 `JNI_OnLoad` 函数");
        return;
    }

    // Hook `JNI_OnLoad`
    Interceptor.attach(jniOnLoad, {
        onEnter(args) {
            console.log("[Hooked] JNI_OnLoad 被调用");
        }
    });
}

function hook_dlopen() {
    ["android_dlopen_ext", "dlopen"].forEach(funcName => {
        let addr = Module.findExportByName(null, funcName);
        if (addr) {
            Interceptor.attach(addr, {
                onEnter(args) {
                    let libName = ptr(args[0]).readCString();
                    if (libName && libName.indexOf(TARGET_LIB_NAME) >= 0) {
                        this.is_can_hook = true;
                        console.log(`[+] ${funcName} onEnter: ${libName}`);
                    }
                },
                onLeave: function (retval) {
                    if (this.is_can_hook) {
                        console.log(`[+] ${funcName} onLeave, start hook JNI_OnLoad`);
                        hook_JNI_OnLoad();
                    }
                }
            });
        }
    });
}

hook_dlopen();
```

**代码要点：**

1. 先 Hook `dlopen`/`android_dlopen_ext` 检测目标库加载
2. 在 `onLeave` 中（库已加载，但 `JNI_OnLoad` 还未调用）安装 `JNI_OnLoad` 的 Hook
3. `Module.findExportByName` 可能找不到被隐藏的 `JNI_OnLoad`，需要遍历符号作为备选
4. 这种延时 Hook 策略是 Part9 中延迟 Hook 技术的基础

### 4.3 在 JNI_OnLoad 中拦截 RegisterNatives

```javascript
// 在 JNI_OnLoad 执行期间动态替换 RegisterNatives 的参数
function hook_JNI_OnLoad_replace_natives() {
    var jniOnLoad = Module.findExportByName(TARGET_LIB_NAME, "JNI_OnLoad");
    if (!jniOnLoad) return;
    
    Interceptor.attach(jniOnLoad, {
        onEnter: function(args) {
            console.log("[JNI_OnLoad] Entered");
            
            // 在 JNI_OnLoad 中，目标会调用 RegisterNatives
            // 我们可以 Hook RegisterNatives 来拦截注册过程
            hook_RegisterNatives_for_modification();
        }
    });
}
```

## 5. Hook RegisterNatives 追踪所有 JNI 注册

`RegisterNatives` 是 `libart.so`（或 `libdvm.so`）中的导出函数，Hook 它可以追踪进程中所有 SO 的动态 JNI 注册：

```javascript
// 引用：awesomeFrida/hook_RegisterNatives.js（完整代码69行）
function hook_RegisterNatives() {
    // 1. 在 libart.so 中查找 RegisterNatives 符号
    var symbols = Module.enumerateSymbolsSync("libart.so");
    var addrRegisterNatives = null;
    
    for (var i = 0; i < symbols.length; i++) {
        var symbol = symbols[i];
        // 匹配 C++ mangled 名称：_ZN3art3JNI15RegisterNativesEP7_JNIEnvP7_jclassPK15JNINativeMethodi
        if (symbol.name.indexOf("art") >= 0 &&
            symbol.name.indexOf("JNI") >= 0 &&
            symbol.name.indexOf("RegisterNatives") >= 0 &&
            symbol.name.indexOf("CheckJNI") < 0) {
            addrRegisterNatives = symbol.address;
            console.log("RegisterNatives is at " + symbol.address + " " + symbol.name);
        }
    }

    // 2. Hook RegisterNatives
    if (addrRegisterNatives != null) {
        Interceptor.attach(addrRegisterNatives, {
            onEnter: function(args) {
                console.log("[RegisterNatives] method_count: " + args[3]);
                
                var env = args[0];
                var java_class = args[1];
                var class_name = Java.vm.tryGetEnv().getClassName(java_class);
                
                var methods_ptr = ptr(args[2]);
                var method_count = parseInt(args[3]);
                
                // 3. 遍历所有注册的方法
                for (var i = 0; i < method_count; i++) {
                    // JNINativeMethod 结构体：
                    //   [0] name      → 方法名指针
                    //   [1] signature → 签名指针
                    //   [2] fnPtr     → C 函数指针
                    var name_ptr = Memory.readPointer(
                        methods_ptr.add(i * Process.pointerSize * 3));
                    var sig_ptr = Memory.readPointer(
                        methods_ptr.add(i * Process.pointerSize * 3 + Process.pointerSize));
                    var fnPtr_ptr = Memory.readPointer(
                        methods_ptr.add(i * Process.pointerSize * 3 + Process.pointerSize * 2));

                    var methodName = Memory.readCString(name_ptr);
                    var sig = Memory.readCString(sig_ptr);
                    var find_module = Process.findModuleByAddress(fnPtr_ptr);
                    
                    if (find_module) {
                        console.log("[RegisterNatives] java_class: " + class_name + 
                                  " name: " + methodName + 
                                  " sig: " + sig + 
                                  " fnPtr: " + fnPtr_ptr + 
                                  " module_name: " + find_module.name + 
                                  " module_base: " + find_module.base + 
                                  " offset: " + ptr(fnPtr_ptr).sub(find_module.base));
                    } else {
                        console.log("[RegisterNatives] java_class: " + class_name + 
                                  " name: " + methodName + 
                                  " sig: " + sig + 
                                  " fnPtr: " + fnPtr_ptr + 
                                  " module: null");
                    }
                }
            }
        });
    }
}

setImmediate(hook_RegisterNatives);
```

**代码要点分析：**

1. **符号搜索**：在 `libart.so` 中搜索 `RegisterNatives` 的 C++ mangled 名称
2. **参数解析**：
   - `args[0]` = `JNIEnv*`
   - `args[1]` = `jclass`（Java 类）
   - `args[2]` = `JNINativeMethod*`（方法结构体数组）
   - `args[3]` = `jint`（方法数量）
3. **JNINativeMethod 结构体遍历**：每个方法三个指针大小（方法名、签名、函数指针）
4. **模块定位**：通过 `Process.findModuleByAddress(fnPtr_ptr)` 确定 C 函数属于哪个 SO

## 6. 静态注册 vs 动态注册对比

| 对比维度 | 静态注册 | 动态注册 |
|---------|---------|---------|
| 实现方式 | 遵循命名约定，自动导出 | JNI_OnLoad + RegisterNatives |
| 符号表可见性 | `.dynsym` 中可见（`Java_com_xxx`） | 函数名可任意，不暴露完整路径 |
| 查找方式 | `Module.getExportByName("Java_com_xxx")` | `Module.getExportByName("any_name")` |
| Hook 时机 | 任意时间（符号始终可访问） | 必须在 JNI_OnLoad 执行后 |
| 逆向难度 | 低（函数名暴露包名类名） | 中（配合 Hook RegisterNatives） |
| 加固绕过 | 更容易被静态定位 | 可动态改变绑定关系 |
| 性能 | 略慢（首次需要符号查找） | 略快（直接函数指针调用） |

## 7. 实战技巧

### 7.1 快速判断注册方式

```bash
# 检查是否有 Java_com_ 前缀的导出符号
readelf -s libtarget.so | grep Java_

# 有输出 → 存在静态注册
# 无输出 → 全动态注册，需 Hook JNI_OnLoad 或 RegisterNatives
```

### 7.2 通过 Frida 同时 Hook 两种注册方式的函数

```javascript
// 针对静态注册+动态注册混合使用的 SO 进行全面 Hook
function hook_all_jni_functions(moduleName) {
    var mod = Process.findModuleByName(moduleName);
    if (!mod) return;
    
    // 1. Hook 静态注册函数（通过符号名直接定位）
    var exports = mod.enumerateExports();
    exports.forEach(function(exp) {
        if (exp.name.indexOf("Java_") === 0) {
            Interceptor.attach(exp.address, {
                onEnter: function(args) {
                    console.log("[static] " + exp.name + " called");
                    console.log("  env=" + args[0] + " obj=" + args[1]);
                },
                onLeave: function(retval) {
                    console.log("[static] " + exp.name + " returned");
                }
            });
        }
    });
    
    // 2. 对于动态注册的函数，需要在 JNI_OnLoad 执行后通过
    //    Hook RegisterNatives 来获取映射关系，然后再 Hook
    console.log("[*] Static registered functions hooked: " + 
                exports.filter(e => e.name.indexOf("Java_") === 0).length);
}
```

## 总结

- **静态注册**：通过 `Java_com_xxx_yyy` 命名规则自动注册，符号名暴露 Java 类路径，易于定位
- **动态注册**：通过 `JNI_OnLoad` + `RegisterNatives` 注册，函数名灵活，更隐蔽
- **JNI_OnLoad Hook**：在 `dlopen` onLeave 后安装 Hook，可拦截动态注册过程
- **RegisterNatives Hook**：在 `libart.so` 中搜索 `RegisterNatives` 符号，可监控所有 JNI 注册
- 实际 SO 中两种注册方式可以**混合使用**，需要全面覆盖两种方式的 Hook 策略
