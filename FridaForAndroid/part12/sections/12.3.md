# 12.3 Protobuf/gRPC协议逆向

> 核心要点：越来越多的 Android App 使用 gRPC（基于 HTTP/2 + Protobuf）替代传统 REST API。本章涵盖 gRPC Hook 方法、Protobuf 序列化拦截、Binder 通信监控三大技术，帮助逆向分析基于 Protobuf 的二进制网络协议。

## 1. gRPC 与 Protobuf 基础

### 1.1 协议栈对比

```
传统 REST API：                    gRPC：
HTTP 1.1 + JSON/XML               HTTP/2 + Protobuf
    ↓                                   ↓
明文文本，可直接抓包             二进制协议，抓包需额外处理
    ↓                                   ↓
curl / Postman 可直接调试         需要 protoc 和反射支持
```

### 1.2 gRPC 在 Android 中的架构

```
Android App
    ↓
gRPC Stub（自动生成的 Java 类）
    ↓
gRPC Channel（网络通道）
    ↓
HTTP/2 帧（二进制）
    ↓
Protobuf 序列化/反序列化
    ↓
Socket / OkHttp 传输
```

**关键 Hook 点：**

| Hook 目标 | 层级 | 用途 |
|:----------|:-----|:------|
| `io.grpc.internal.ClientCallImpl` | gRPC 核心 | 拦截 RPC 调用 |
| `MethodDescriptor` | 方法描述 | 获取 RPC 方法名 |
| Protobuf 生成的 Java 类 | 序列化层 | 拦截序列化/反序列化 |
| BinderProxy.transact | IPC 层 | 监控 Binder 调用 |

## 2. gRPC Hook 方案

### 2.1 拦截 gRPC 客户端调用

```javascript
// gRPC 核心调用 Hook
function hookGrpcClientCall() {
    Java.perform(function () {
        try {
            var ClientCall = Java.use("io.grpc.internal.ClientCallImpl");
            
            // Hook start 方法
            ClientCall.start.overload(
                'io.grpc.ClientCall$Listener', 'io.grpc.Metadata'
            ).implementation = function (listener, headers) {
                console.log("[gRPC] ClientCall.start called");
                console.log("[gRPC] Headers: " + headers.toString());
                // 打印调用堆栈，定位调用源
                printStack();
                return this.start(listener, headers);
            };

            // Hook sendMessage 拦截请求体
            ClientCall.sendMessage.implementation = function (message) {
                console.log("[gRPC] sendMessage called");
                // 尝试解析 Protobuf 消息
                try {
                    var msgStr = message.toString();
                    console.log("[gRPC] Message: " + msgStr);
                } catch (e) {
                    console.log("[gRPC] Message (toString failed): " + e);
                }
                return this.sendMessage(message);
            };

            // Hook halfClose 标记请求结束
            ClientCall.halfClose.implementation = function () {
                console.log("[gRPC] halfClose - request completed");
                return this.halfClose();
            };
        } catch (e) {
            console.log("[gRPC] ClientCall not found: " + e);
        }
    });
}
```

### 2.2 拦截 gRPC 方法描述

```javascript
// 获取 gRPC 方法名称和类型
function hookGrpcMethodDescriptor() {
    Java.perform(function () {
        try {
            var MethodDescriptor = Java.use("io.grpc.MethodDescriptor");
            
            // Hook 方法描述构建器
            var Builder = Java.use("io.grpc.MethodDescriptor$Builder");
            Builder.build.implementation = function () {
                var result = this.build();
                console.log("[gRPC] Method: " + result.getFullMethodName());
                console.log("[gRPC] Type: " + result.getType());
                return result;
            };
        } catch (e) {
            console.log("[gRPC] MethodDescriptor not found: " + e);
        }
    });
}
```

### 2.3 拦截 Protobuf 序列化/反序列化

```javascript
// 拦截 Protobuf 消息的序列化和反序列化
function hookProtobufSerialization() {
    Java.perform(function () {
        // 方案一：Hook 所有 GeneratedMessageLite 的子类
        Java.enumerateLoadedClasses({
            onMatch: function (className) {
                if (className.indexOf('com.google.protobuf.') >= 0 ||
                    className.indexOf('proto') >= 0 ||
                    className.indexOf('Protobuf') >= 0) {
                    //console.log("Protobuf class found: " + className);
                }
            },
            onComplete: function () { }
        });

        // 方案二：Hook 通用的序列化方法
        try {
            var GeneratedMessageLite = Java.use(
                "com.google.protobuf.GeneratedMessageLite"
            );
            
            // Hook toByteArray — 序列化
            GeneratedMessageLite.toByteArray.implementation = function () {
                var result = this.toByteArray();
                console.log("[Protobuf] Serialized: " + result.length + " bytes");
                var ByteString = Java.use("com.android.okhttp.okio.ByteString");
                console.log("[Protobuf] Hex: " + ByteString.of(result).hex());
                return result;
            };

            // Hook parseFrom — 反序列化
            var parseMethods = GeneratedMessageLite.class.getDeclaredMethods();
            // 需要获取具体的 Builder 或静态 parseFrom 方法
        } catch (e) {
            console.log("[Protobuf] GeneratedMessageLite not found: " + e);
        }

        // 方案三：Hook protobuf-lite 的 CodedInputStream/CodedOutputStream
        try {
            var CodedOutputStream = Java.use(
                "com.google.protobuf.CodedOutputStream"
            );
            CodedOutputStream.writeMessageSetExtension.implementation = function () {
                console.log("[Protobuf] CodedOutputStream.writeMessageSetExtension");
                return this.writeMessageSetExtension.apply(this, arguments);
            };
        } catch (e) {
            console.log("[Protobuf] CodedOutputStream not found: " + e);
        }
    });
}
```

## 3. Binder 通信监控

当 App 使用跨进程通信（IPC）时，数据通过 Binder 驱动传输。监控 Binder 调用可以捕获跨进程的 Protobuf 数据。

### 3.1 BinderProxy Hook

> **引用源文件**：`awesomeFrida/BinderProxy.js`（完整40行代码）

```javascript
// 引用：awesomeFrida/BinderProxy.js 完整代码
function hookBinderProxy() {
    // 用于添加追踪
    const Trace = Java.use('android.os.Trace');
    // 用于获取调用堆栈
    const Thread = Java.use('java.lang.Thread');
    // Hook BinderProxy 的 transact 方法
    const BinderProxy = Java.use('android.os.BinderProxy');

    // Hook transact 方法
    BinderProxy.transact.implementation = function (...args) {
        // 获取调用堆栈
        const stacktrace = Thread.currentThread().getStackTrace();
        // Binder 调用通常在堆栈的第 4 层
        const callingStack = stacktrace[3];
        // 开始追踪
        Trace.beginSection(callingStack.toString());
        // 执行原始调用
        var result = this.transact(...args);
        // 结束追踪
        Trace.endSection();
        return result;
    };
}

// 打印堆栈
function printStack() {
    Java.perform(function () {
        console.log(Java.use("android.util.Log").getStackTraceString(
            Java.use("java.lang.Exception").$new()
        ));
    });
}
```

### 3.2 Binder 事务代码分析

Binder 调用通过 `transact(code, data, reply, flags)` 传递数据，其中 `code` 是事务代码：

```javascript
// 增强版 BinderProxy Hook：打印事务代码和数据
function hookBinderProxyAdvanced() {
    Java.perform(function () {
        const BinderProxy = Java.use('android.os.BinderProxy');
        const Parcel = Java.use('android.os.Parcel');

        BinderProxy.transact.overload(
            'int', 'android.os.Parcel', 'android.os.Parcel', 'int'
        ).implementation = function (code, data, reply, flags) {
            // 事务代码映射
            var codeMap = {
                1: "PING_TRANSACTION",
                2: "DUMP_TRANSACTION",
                3: "SHELL_COMMAND_TRANSACTION",
                // 不同 Service 有各自的 code
            };
            var codeName = codeMap[code] || "UNKNOWN_TRANSACTION(" + code + ")";
            console.log("[Binder] transact: " + codeName);

            // 读取 Parcel 数据（部分）
            try {
                var dataSize = data.dataSize();
                if (dataSize > 0) {
                    console.log("[Binder] data size: " + dataSize + " bytes");
                    // 可以尝试读取 Parcel 中的各项数据
                }
            } catch (e) {
                console.log("[Binder] data read error: " + e);
            }

            return this.transact(code, data, reply, flags);
        };

        // 额外的调用堆栈定位
        printStack();
    });
}
```

## 4. 实战：解析 gRPC 流量

### 4.1 完整的 gRPC 嗅探脚本

```javascript
// 完整的 gRPC 流量嗅探脚本
function hookGrpcFull() {
    Java.perform(function () {
        // 1. 定位 gRPC 方法名
        try {
            var Channel = Java.use("io.grpc.Channel");
            Channel.newCall.implementation = function (methodDescriptor, callOptions) {
                console.log("[gRPC] newCall: " + methodDescriptor.getFullMethodName());
                var result = this.newCall(methodDescriptor, callOptions);
                return result;
            };
        } catch (e) {
            console.log("[gRPC] Channel.newCall not found");
        }

        // 2. 拦截请求/响应监听器
        try {
            var ClientCall = Java.use("io.grpc.ClientCall");
            ClientCall.start.overload(
                'io.grpc.ClientCall$Listener', 'io.grpc.Metadata'
            ).implementation = function (listener, headers) {
                console.log("[gRPC] ClientCall.start");
                // 包装原始 Listener 来拦截 onMessage
                var originalListener = listener;
                var wrappedListener = Java.registerClass({
                    name: "com.hermes.GrpcListenerWrapper",
                    superClass: Java.use("io.grpc.ClientCall$Listener"),
                    methods: {
                        onMessage: function (message) {
                            console.log("[gRPC] Response received");
                            try {
                                console.log("[gRPC] Response: " + message.toString());
                            } catch (e) {
                                console.log("[gRPC] Response parse error: " + e);
                            }
                            originalListener.onMessage(message);
                        },
                        onClose: function (status, trailers) {
                            console.log("[gRPC] onClose: " + status.toString());
                            originalListener.onClose(status, trailers);
                        },
                        onHeaders: function (headers) {
                            console.log("[gRPC] onHeaders: " + headers.toString());
                            originalListener.onHeaders(headers);
                        },
                        onReady: function () {
                            originalListener.onReady();
                        }
                    }
                });
                return this.start(wrappedListener.$new(), headers);
            };
        } catch (e) {
            console.log("[gRPC] ClientCall.start hook failed: " + e);
        }

        // 3. 将发送的消息也记录下来
        try {
            var ClientCallImpl = Java.use("io.grpc.internal.ClientCallImpl");
            ClientCallImpl.sendMessage.implementation = function (message) {
                console.log("[gRPC] Sending message");
                try {
                    console.log("[gRPC] Message content: " + message.toString());
                } catch (e) { }
                return this.sendMessage(message);
            };
        } catch (e) {
            console.log("[gRPC] sendMessage hook failed");
        }
    });
}

// Hook BinderProxy 监控 IPC 调用
function hookBinder() {
    Java.perform(function () {
        const BinderProxy = Java.use('android.os.BinderProxy');
        BinderProxy.transact.implementation = function (...args) {
            console.log("[Binder] transact called");
            printStack();
            return this.transact(...args);
        };
    });
}

// 打印堆栈
function printStack() {
    console.log(Java.use("android.util.Log").getStackTraceString(
        Java.use("java.lang.Exception").$new()
    ));
}

function main() {
    hookGrpcFull();
    // hookBinder();  // 按需启用
}

setImmediate(main);
```

## 5. Proto 文件还原

### 5.1 从内存中重建 Proto 定义

在逆向过程中，如果无法直接获取 `.proto` 文件，可以通过以下方式重建：

```javascript
// 枚举 Protobuf 相关的类并打印结构
function enumerateProtobufClasses() {
    Java.perform(function () {
        Java.enumerateLoadedClasses({
            onMatch: function (className) {
                if (className.indexOf("Proto") >= 0 ||
                    className.indexOf("protobuf") >= 0 ||
                    className.match(/\.(Request|Response|Builder)$/)) {
                    
                    console.log("Potential Protobuf class: " + className);
                    
                    try {
                        var clazz = Java.use(className);
                        // 枚举字段（通过反射或已知方法）
                        var methods = clazz.class.getDeclaredMethods();
                        for (var i = 0; i < methods.length; i++) {
                            var methodName = methods[i].getName();
                            if (methodName.startsWith("get") ||
                                methodName.startsWith("set") ||
                                methodName.startsWith("has")) {
                                console.log("  Method: " + methodName);
                            }
                        }
                    } catch (e) {
                        // 某些内部类可能无法直接 use
                    }
                }
            },
            onComplete: function () {
                console.log("Protobuf class enumeration done");
            }
        });
    });
}
```

### 5.2 使用 protoc 反序列化

如果获取到了二进制 Protobuf 数据，且已知 `.proto` 文件：

```bash
# 使用 protoc 反序列化
protoc --decode_raw < binary_data.bin
protoc --decode=my.package.MyMessage my.proto < binary_data.bin
```

## 6. 常见问题与排查

| 问题 | 可能原因 | 解决方案 |
|:----|:---------|:---------|
| **找不到 gRPC 类** | App 使用 gRPC-java 但混淆重命名 | 使用 `Java.enumerateLoadedClasses` 搜索 |
| **Protobuf 消息为空** | 序列化优化（如裁剪字段名） | 使用 `CodedOutputStream` 级别 Hook |
| **Binder Hook 不触发** | App 使用 aidl 直接调用 | Hook `android.os.Binder.execTransact` |
| **无法解析二进制数据** | 缺少 .proto 文件 | 使用 `protoc --decode_raw` 尝试猜测 |
| **性能严重下降** | gRPC 调用频繁，输出过多 | 添加频率限制或条件过滤 |

## 小结

- **gRPC 逆向**的关键是 Hook `ClientCallImpl` 的 `start`、`sendMessage` 方法和 `Listener` 的 `onMessage`、`onClose` 回调
- **Protobuf 序列化拦截**可以通过 Hook `GeneratedMessageLite.toByteArray` 实现，但更可靠的是 Hook `CodedOutputStream` 和 `CodedInputStream`
- **Binder 通信监控**通过 Hook `BinderProxy.transact` 实现，配合 `awesomeFrida/BinderProxy.js` 可以追踪跨进程调用
- **Proto 文件还原**是逆向 gRPC 的核心难点，需要结合类枚举、反射调用和 protoc 工具链

> **参考源文件**：`awesomeFrida/BinderProxy.js`（40行）、`awesomeFrida/r0capture.js`（Socket 读写监控部分）
