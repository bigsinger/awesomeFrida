# 12.1 电商App抓包方案

> 核心要点：电商 App 通常采用多层安全防护（OkHttp 自定义拦截器、SSL Pinning、HTTPDNS 等），单一的 Hook 方案无法覆盖所有场景。本章将组合使用 **OkHttp Hook + Socket Hook + SSL 绕过** 三层方案，实现全方位无死角的网络请求捕获。

## 1. 电商 App 常见防护手段

典型电商 App 的网络安全架构：

```
流量层                   防护措施
┌─────────────────────────────────────────────────┐
│  OkHttp 请求         自定义拦截器、HTTPDNS       │
│       ↓                                          │
│  TLS/SSL 层          SSL Pinning、双向认证       │
│       ↓                                          │
│  Socket 层           自定义协议、非标准端口      │
│       ↓                                          │
│  传输层               TCP/UDP 加密隧道           │
└─────────────────────────────────────────────────┘
```

| 防护手段 | 常见实现 | 应对策略 |
|:--------|:---------|:---------|
| OkHttp 自定义拦截器 | 请求/响应加解密、签名校验 | 拦截器注入 + newCall Hook |
| SSL Pinning | 证书固定、公钥固定 | JustTrustMe / r0capture |
| BoringSSL（Chromium 系） | 字节系 App 使用 cronet | `SSL_CTX_set_custom_verify` Hook |
| HTTPDNS | 自定义 DNS 解析 | Hook InetAddress |
| Socket 加密 | 在 Socket 读写时加解密 | SocketOutputStream Hook |
| 双向认证 | 服务器校验客户端证书 | r0capture 自动 Dump 客户端证书 |

## 2. 第一层：OkHttp Hook

### 2.1 newCall Hook（快速定位）

最简单的切入点。Hook OkHttpClient.newCall 方法可以捕获所有通过 OkHttp 发起的请求的 Request 对象：

> **引用源文件**：`Chap08/hookNewCall.js`（完整14行代码） / `awesomeFrida/hookUrl.js` 第72-83行

```javascript
// 引用：awesomeFrida/hookUrl.js 第72-83行
function hookOkHttpClient() {
    try {
        var OkHttpClient = Java.use("okhttp3.OkHttpClient");
        OkHttpClient.newCall.implementation = function (request) {
            var result = this.newCall(request);
            console.log(request.toString());
            return result;
        };
    } catch (error) {
        console.log(error);
    }
}
```

**适用场景**：快速确认 App 是否使用 OkHttp、查看请求 URL 和方法。

### 2.2 拦截器注入方案（深度 Hook）

> **引用源文件**：`awesomeFrida/hook_okhttp3.js`（完整120行代码）

当需要查看完整的请求/响应体时，使用 Java.registerClass 动态创建 OkHttp Interceptor：

```javascript
// 引用：awesomeFrida/hook_okhttp3.js 第1-20行（核心部分）
function hook_okhttp3() {
    Java.perform(function () {
        var ByteString = Java.use("com.android.okhttp.okio.ByteString");
        var Buffer = Java.use("com.android.okhttp.okio.Buffer");
        var Interceptor = Java.use("okhttp3.Interceptor");
        var ArrayList = Java.use("java.util.ArrayList");
        var OkHttpClient = Java.use("okhttp3.OkHttpClient");

        // 注册自定义拦截器
        var MyInterceptor = Java.registerClass({
            name: "okhttp3.MyInterceptor",
            implements: [Interceptor],
            methods: {
                intercept: function (chain) {
                    var request = chain.request();
                    // ... 输出请求头、请求体 ...
                    var response = chain.proceed(request);
                    // ... 输出响应头、响应体 ...
                    return response;
                }
            }
        });
    });
}
```

**关键操作**：

```
Builder.build.implementation → 替换所有拦截器为自定义拦截器
Builder.addInterceptor.implementation → 拦截添加拦截器的操作
OkHttpClient.$init.overload → 监控初始化
```

**使用注意事项**：

```javascript
// 在 Builder.build 中注入自定义拦截器
Builder.build.implementation = function () {
    this.interceptors().clear();
    this.interceptors().add(MyInterceptorObj);
    var result = this.build();
    return result;
};
```

### 2.3 预编译 Dex 方案（OkHttpLogger-Frida）

> **引用来源**：`Chap08/OkHttpLogger-Frida`

另一种成熟方案是使用预编译的 OkHttp 日志拦截器 Dex 文件：

```javascript
// 引用：Chap08/hookInteceptor.js 完整代码
function hook_okhttp3() {
    Java.perform(function () {
        // 加载预编译的 Dex（需提前 push 到 /data/local/tmp/）
        Java.openClassFile("/data/local/tmp/okhttp3logging.dex").load();

        var MyInterceptor = Java.use("com.r0ysue.okhttp3demo.LoggingInterceptor");
        var MyInterceptorObj = MyInterceptor.$new();
        var Builder = Java.use("okhttp3.OkHttpClient$Builder");

        Builder.build.implementation = function () {
            this.networkInterceptors().add(MyInterceptorObj);
            return this.build();
        };
    });
}
```

**Dex 方案的优点**：
- 代码量更少，结构更清晰
- 可维护性更好，日志逻辑可预先编译
- 支持复杂的日志格式和自定义处理

## 3. 第二层：Socket Hook

当 OkHttp 层 Hook 无效时（App 使用了自定义网络库或原生 Socket），退守 Socket 层。

### 3.1 普通 Socket 读写 Hook

> **引用源文件**：`Chap08/hookSocket.js` 第25-57行

```javascript
// 引用：Chap08/hookSocket.js 第25-56行
function hookSocket() {
    Java.perform(function () {
        // Socket 发送数据
        Java.use('java.net.SocketOutputStream').socketWrite.overload(
            '[B', 'int', 'int'
        ).implementation = function (bytearray1, int1, int2) {
            var result = this.socketWrite(bytearray1, int1, int2);
            var ByteString = Java.use("com.android.okhttp.okio.ByteString");
            jhexdump(bytearray1);
            return result;
        };

        // Socket 接收数据
        Java.use('java.net.SocketInputStream').read.overload(
            '[B', 'int', 'int'
        ).implementation = function (bytearray1, int1, int2) {
            var result = this.read(bytearray1, int1, int2);
            jhexdump(bytearray1);
            return result;
        };
    });
}
```

### 3.2 SSL Socket Hook（Android 8+）

> **引用源文件**：`Chap08/hookSocket.js` 第60-92行

Android 8（API 26）及以上版本使用 Conscrypt 作为 SSL 提供者，SSL Socket 的读写类路径发生变化：

```javascript
// 引用：Chap08/hookSocket.js 第60-92行（Android 8+ SSL Socket Hook）
function hookSSLSocketAndroid8() {
    Java.perform(function () {
        // Android 8+: com.android.org.conscrypt.ConscryptFileDescriptorSocket
        Java.use(
            'com.android.org.conscrypt.ConscryptFileDescriptorSocket$SSLOutputStream'
        ).write.overload('[B', 'int', 'int').implementation = function (bytearray1, int1, int2) {
            var result = this.write(bytearray1, int1, int2);
            var ByteString = Java.use("com.android.okhttp.okio.ByteString");
            console.log('SSL Write contents: => ', ByteString.of(bytearray1).hex());
            return result;
        };

        Java.use(
            'com.android.org.conscrypt.ConscryptFileDescriptorSocket$SSLInputStream'
        ).read.overload('[B', 'int', 'int').implementation = function (bytearray1, int1, int2) {
            var result = this.read(bytearray1, int1, int2);
            jhexdump(bytearray1);
            return result;
        };
    });
}
```

对于 Android 7 及以下版本，使用 OpenSSLSocketImpl：

```javascript
// Android 7-: com.android.org.conscrypt.OpenSSLSocketImpl
Java.use("com.android.org.conscrypt.OpenSSLSocketImpl$SSLOutputStream")
Java.use("com.android.org.conscrypt.OpenSSLSocketImpl$SSLInputStream")
```

### 3.3 地址定位补充

Hook `InetSocketAddress` 可以同时获取连接的目标地址和端口：

```javascript
// 引用：Chap08/hookSocket.js 第8-23行
Java.use('java.net.InetSocketAddress').$init.overload(
    'java.net.InetAddress', 'int'
).implementation = function(addr, port) {
    var result = this.$init(addr, port);
    if(addr.isSiteLocalAddress()) {
        console.log('Local address =>', addr.toString(), ', port is ', port);
    } else {
        console.log('Server address =>', addr.toString(), ', port is ', port);
    }
    return result;
};
```

## 4. 第三层：SSL 绕过

### 4.1 r0capture 通杀方案

> **引用源文件**：`awesomeFrida/r0capture.js`（完整338行代码）

r0capture 是目前最完善的通杀 SSL 抓包方案，核心原理：

```
r0capture 架构
├── Native 层：Hook SSL_read / SSL_write → 捕获加解密后的明文数据
├── Java 层：Hook SocketOutputStream / InputStream → 捕获 HTTP 明文
├── 证书导出：Hook KeyStore.getPrivateKey → Dump 客户端证书为 .p12
└── SSL Pinning 定位：Hook File.$init → 定位证书固定代码位置
```

**核心 Hook 点（Native 层）：**

```javascript
// 引用：awesomeFrida/r0capture.js 第189-219行
// Hook SSL_read 获取解密后的数据
Interceptor.attach(addresses["SSL_read"], {
    onEnter: function (args) {
        var message = getPortsAndAddresses(SSL_get_fd(args[0]), true);
        message["ssl_session_id"] = getSslSessionId(args[0]);
        message["function"] = "SSL_read";
        this.message = message;
        this.buf = args[1];
    },
    onLeave: function (retval) {
        retval |= 0;
        if (retval <= 0) return;
        send(this.message, Memory.readByteArray(this.buf, retval));
    }
});

// Hook SSL_write 捕获发送前的明文
Interceptor.attach(addresses["SSL_write"], {
    onEnter: function (args) {
        var message = getPortsAndAddresses(SSL_get_fd(args[0]), false);
        message["ssl_session_id"] = getSslSessionId(args[0]);
        message["function"] = "SSL_write";
        send(message, Memory.readByteArray(args[1], parseInt(args[2])));
    }
});
```

**客户端证书导出功能：**

```javascript
// 引用：awesomeFrida/r0capture.js 第238-259行
// 在服务器校验客户端证书的场景下自动 Dump 证书为 .p12 格式
Java.use("java.security.KeyStore$PrivateKeyEntry").getPrivateKey.implementation = function () {
    var result = this.getPrivateKey();
    var packageName = Java.use("android.app.ActivityThread")
        .currentApplication().getApplicationContext().getPackageName();
    storeP12(this.getPrivateKey(), this.getCertificate(),
        '/sdcard/Download/' + packageName + '.p12', 'r0ysue');
    return result;
};
```

**运行方式：**

```bash
# 基础 SSL 抓包
frida -U -f com.example.shop -l r0capture.js

# 指定 SSL 库（某些 App 使用自定义编译的 OpenSSL）
frida -U -f com.example.shop -l r0capture.js --no-pause
# 然后通过 RPC 设置 SSL 库
# rpc.setssllib("libcustomssl.so")
```

### 4.2 字节系 BoringSSL 绕过

> **引用源文件**：`awesomeFrida/byPassSSL.js` / `awesomeFrida/byteDance.js`

字节跳动系 App（抖音、今日头条等）使用自带的 `libsscronet.so`（基于 Chromium BoringSSL），需使用专门的绕过方案：

```javascript
// 引用：awesomeFrida/byPassSSL.js 完整代码（核心通杀方法）
function main() {
    Java.perform(function () {
        const soName = 'libsscronet.so';
        onLoad(soName, () => {
            let SSL_CTX_set_custom_verify = Module.getExportByName(
                soName, 'SSL_CTX_set_custom_verify'
            );
            if (SSL_CTX_set_custom_verify != null) {
                Interceptor.attach(SSL_CTX_set_custom_verify, {
                    onEnter: function (args) {
                        // Hook 回调参数——custom_verify_callback
                        Interceptor.attach(args[2], {
                            onLeave: function (retval) {
                                // 将验证结果全部替换为 ssl_verify_ok
                                if (retval > 0x0) retval.replace(0x0);
                            }
                        });
                    }
                });
            }
        });
    });
}
```

**byteDance.js** 提供了三种绕过方法：

| 方法 | 原理 | 优点 | 缺点 |
|:----|:-----|:-----|:-----|
| 方法1：内存搜索 | 搜索特征字节定位 patch 点 | 不依赖符号 | 稳定性差 |
| 方法2：直接 Patch | 根据固定偏移 patch | 简单直接 | 版本依赖度高 |
| 方法3：Hook SSL_CTX_set_custom_verify | 替换验证回调返回值 | 通杀性强 | 需符号存在 |

## 5. 完整使用流程

### 5.1 常用 URL 监控

> **引用源文件**：`awesomeFrida/hookUrl.js`

除了 OkHttp 和 Socket Hook，组合使用 URL 和 Header 监控可以快速定位关键请求：

```javascript
// 引用：awesomeFrida/hookUrl.js 第12-35行
function hookURL() {
    var URL = Java.use('java.net.URL');
    URL.$init.overload('java.lang.String').implementation = function (a) {
        console.log('URL：' + a);
        this.$init(a);
    }
}

function hookOkhttp3() {
    try {
        var Builder = Java.use('okhttp3.Request$Builder');
        Builder.url.overload('okhttp3.HttpUrl').implementation = function (a) {
            console.log('okhttp3.HttpUrl: ' + a);
            return this.url(a);
        }
    } catch (error) { }
}
```

### 5.2 实战组合方案

针对电商 App 的推荐方案组合：

```bash
# 方案一：常规组合（适合大多数 App）
frida -U -f com.example.shop \
  -l r0capture.js \

  -l byteDance.js \
```

## 6. 常见问题与排查

| 问题 | 可能原因 | 解决方案 |
|:----|:---------|:---------|
| **OkHttp Hook 无效** | App 使用自定义网络库 | 使用 Socket Hook 方案 |
| **SSL 绕过失效** | App 使用 BoringSSL 或自定义 SSL | 尝试 r0capture + 指定 SSL 库 |
| **Socket Hook 无输出** | App 使用 Native 层 Socket | 使用 Stalker 追踪 Native 网络函数 |
| **脚本冲突** | 多个脚本同时 Hook 同一类 | 合并脚本或使用条件判断 |
| **抓包数据乱码** | 数据经过压缩（GZip）或加密 | 添加压缩/加密处理逻辑 |
| **部分请求未捕获** | 使用了非标准 OkHttp 初始化方式 | Hook OkHttpClient.Builder.build 的所有重载 |

## 小结

- **三层 Hook 方案**是电商 App 抓包的完整解决方案：OkHttp 层 → Socket 层 → SSL 层
- **OkHttp 层**最适合捕获结构化 HTTP 请求，通过拦截器注入或 newCall Hook 实现
- **Socket 层**作为兜底方案，捕获所有通过 Java Socket 传输的数据
- **SSL 绕过**是抓包的前提，r0capture 提供一站式的 SSL 读写 Hook + 客户端证书导出
- **字节系 App** 需要使用 BoringSSL 专用绕过方案（`SSL_CTX_set_custom_verify`）
